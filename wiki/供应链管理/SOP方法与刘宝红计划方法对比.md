# SOP方法与刘宝红计划方法对比

> **状态**：unreviewed
> **最后更新**：2026-10-28
> **来源**：[[raw/知识文件归档/亚马逊运营/计划运营SOP课程存档/采购计划下单SOP]]、[[raw/知识文件归档/供应链管理-刘宝红/6、《需求预测和库存计划  一个实践者的角度》2020年]]、[[raw/知识文件归档/供应链管理-刘宝红/3、《供应链的三道防线》2022年]]

## 核心要点

- 两者是**同一件事（补货计划）的两种范式**：SOP 是「库存水位盘点 + 人工销量预估 + 固定参数倒推」的**经验型可执行流程**；刘宝红是「需求历史数据 + 统计模型基线 + 量化安全库存」的**数据型方法论框架**
- **核心映射**：SOP 的"安全库存时间 35 天" = 刘宝红"安全库存量"的**时间化表达**（`安全库存量 = 35 天 × 日销`），二者公式骨架同源，差别只在"安全库存从哪来"——拍出来的固定天数 vs 算出来的不确定性函数
- 刘宝红方法论内核："**从数据开始，由判断结束**"；SOP 的短板恰是"**以判断代数据、一刀切代精细**"
- **最小改动路径**：把【控制日销】从"推广拍的数"升级为"**基准预测（模型）+ 推广增量（判断）**"，即可把刘宝红方法灌进现有表格而不推倒流程

---

## 详细内容

### 一、两种方法各自的数据来源与流程

#### A. SOP 方法（来源：[[raw/知识文件归档/亚马逊运营/计划运营SOP课程存档/采购计划下单SOP]]）

**数据来源（盘点侧 + 判断侧）：**
- **供给侧盘点**（人工逐项核对）：工厂生产订单（已下单未发货）、FBA 实际在库库存（查后台"库存-货件"/AK"FBA-FBA货件"判入库）、在途库存（已发货未入 FBA），落在「销量模拟+库存控制」表
- **需求侧预估**：由**推广**给出销量预估（综合日常控制销量、日常促销、大促、种子链接、断货），落在【控制库存】字段，即"控制日销"
- **参数**：安全库存时间通常 **35 天**、补货频次 **7/14 天**（通常 14 天）、货运周期（物流确认）、生产周期（执行采购+工厂确认）

**流程（线性串行六步）：**
```
① 下单前建单/关联确认 → ② 盘点库存 → ③ 推广给销量预估
→ ④ 套公式倒推时点 → ⑤ 写盘点表 + 总监审批 → ⑥ AK 系统单据 → 采购端下单
```

**核心公式（原文原文）：**
- 发货时间点 = 预估售罄日期 − 安全库存时间 − 货运周期
- 下单时间点 = 预估售罄日期 − 安全库存时间 − 货运周期 − 工厂生产时间
- 补货数量 = 补货频次 × 控制日销

#### B. 刘宝红方法（来源：[[wiki/供应链管理/读书笔记/《供应链的三道防线》]]、[[wiki/供应链管理/读书笔记/《需求预测和库存计划》]]）

**数据来源：**
- **需求历史数据为基石**：发货/订单历史，主张**按周汇总**（样本点多、控制点多），并做**数据清洗**（削峰填谷，剔除促销、断货、打折清仓等一次性扰动）
- **职业判断为辅**：销售/市场的促销计划、新品上市计划，只做**增量调整**（"存量 + 增量"）

**流程（三道防线 + 安全库存三步法）：**
```
第一道防线 需求预测：需求历史 → 基准预测（统计模型）→ 职业判断调整 → 最终预测
第二道防线 库存计划：①量化需求不确定性 → ②量化服务水平/有货率 → ③计算安全库存
第三道防线 供应链执行：赶工加急、供应商快速响应
```

### 二、差异对比表

| 维度 | SOP（经验型） | 刘宝红（数据型） |
|------|--------------|------------------|
| **需求预测来源** | 推广**主观判断**的"控制日销" | **需求历史数据** + 统计模型，判断仅作增量 |
| **历史数据的角色** | 仅作填表参考，无清洗、无建模 | 核心原料，需清洗、建模、复盘 |
| **安全库存** | **一刀切 35 天**（固定天数） | **按不确定性量化**：标准差 + 服务水平 → 差异化计算 |
| **补货触发** | 时点倒推（售罄日 − 各周期） | 再订货点 = 预测 + 安全库存（数量触发） |
| **颗粒度** | 单一 SKU × 单一店铺 | 强调"在合适颗粒度上做预测"（越大越准） |
| **纠偏机制** | 无显式复盘环节 | 滚动预测 + 预测准确度复盘（MAPE/均方误差） |
| **组织定位** | 计划岗照单执行，推广出数、总监拍板 | 计划是**分析型岗位**，"没有人知道得比数据还多" |

### 三、各自的优势与不足

#### SOP 方法的优势
1. **可操作性极强**：六步线性流程 + 固定参数，新人照着表格和系统路径就能做，培训成本低
2. **贴合亚马逊场景**：紧扣 FBA 库存/在途/货件状态/推广节奏/AK 单据，专为跨境电商定制
3. **响应快、责任清**：推广出销量、总监审批，决策链短，能快速应对大促、断货等平台节奏
4. **参数化易执行**：35 天/14 天这类硬参数，避免了"算不出安全库存"的落地障碍

#### SOP 方法的不足
1. **销量预估靠推广拍脑袋**：正是刘宝红反复批判的"业务端提需求"——一线颗粒度小、偏乐观、缺统计基线，易系统性多备或少备
2. **安全库存一刀切**：不分产品波动性、不分价值，35 天对稳定品可能过高、对爆款/长尾可能不足 → 短缺与过剩并存
3. **历史数据被浪费**：只"填表"不"建模"，促销/断货/清仓数据未清洗，无法沉淀出基准预测
4. **无纠偏与复盘闭环**：没有滚动预测、没有准确度度量，预测错了靠下一次人工发现，容易"救火"
5. **参数缺乏依据**：35 天、14 天的取值依据未在 SOP 中说明，换人后不可解释

#### 刘宝红方法的优势
1. **客观、可解释**：基准预测来自数据，减少拍脑袋；决策可追踪、可复盘、可改进
2. **差异化精细管理**：安全库存按不确定性 + 服务水平算，避免"一刀切"造成的结构性库存错配
3. **长期持续改进**：滚动预测 + 准确度复盘，越用越准；数据清洗让模型抗"大错特错"
4. **方法论完备**：三道防线 + 颗粒度 + 新品导入，覆盖 SOP 未覆盖的场景

#### 刘宝红方法的不足
1. **落地门槛高**：需要数据质量、信息系统、统计能力，小团队/个人难直接上手
2. **依赖跨职能协作**："由判断结束"需要稳健的销售-运营协调流程，组织博弈成本高
3. **新品/强促销场景难适配**：亚马逊大促、断货、种子链接等"不可重复"事件多，会打破"需求历史可重复性"这一核心假设
4. **见效慢**：是一套体系化改造，短期不如"固定参数倒推"来得快

> 💡 **LLM 推断**：SOP 不是"错的方法"，而是刘宝红框架在"数据能力尚未建立"阶段的朴素近似——用"推广判断"暂代"统计基线"，用"固定 35 天"暂代"量化安全库存"。

### 四、刘宝红需求预测统计模型（亚马逊场景用法）

> 📌 前提：刘宝红预测的**唯一数据源是"需求历史"**，需求的延续性分三种成分——**随机变动、趋势、周期性（季节性）**，模型按此逐一对应。

| 模型 | 适用场景 | 核心逻辑 | 参数 |
|------|---------|---------|------|
| **幼稚预测**（naive） | 一切模型的**基准线** | 用上期实际值当预测（"卖一补"） | 无 |
| **移动平均法**（MA） | 平稳、无趋势无季节性 | 平均最近 N 期历史，消除随机波动 | 期数 N（2/4/6/8/13 周） |
| **简单指数平滑法**（ES） | 平稳场景，最常用 | 加权移动平均，权重几何级衰减，越新越重 | 平滑系数 α（0~1） |
| **霍尔特法**（Holt） | 有**趋势**（爬坡/下滑） | 水平 + 趋势两部分分别平滑，可外推多期 | α（水平）、β（趋势） |
| **霍尔特-温特**（Holt-Winters） | **趋势 + 季节性**并存 | 水平 + 趋势 + 季节指数三者分解 | α、β、γ |
| **线性回归**（相关性） | **数据有限**（如新品） | 用类似产品的相关性做预测 | 回归系数 R² |
| **长尾产品** | 低频、零散出单 | 正态分布不适用，用**泊松分布**模拟更准 | — |

**关键操作：**
- **数据清洗（削峰填谷）**：剔除促销虚高（削峰）、断货虚低（填谷）的一次性扰动
- **模型择优（复盘回测）**：用老数据复盘预测新数据，比**均方误差（MSE）**，选最小者；MSE 比 MAPE 更靠谱（平方加倍惩罚极端误差，助你避开"大错特错"）
- **颗粒度**：预测按**周汇总**，不要拆到天（杂音大）、也不要用月（控制点太少）

#### 亚马逊场景逐条映射（🔍 综合刘宝红方法与亚马逊业务特点的推断）

1. **成熟稳定款（老品/长销款）→ 简单指数平滑 / 移动平均**：α 取 0.1~0.3 或 6/8 周移动平均；正好替代 SOP 的【控制日销】。数据源用后台「销量查询与更新」/ AK 的 FBA 销量按周汇总。⚠️ 口径要统一（FBA 已售 vs 自发货 vs 退货）
2. **爬坡 / 放量 / 排名上升期 → 霍尔特法**：新品爬坡、加大广告、BSR 持续上升时用；⚠️ 霍尔特有过度外推倾向，需设下限
3. **强季节性产品（旺季/节日款）→ 霍尔特-温特**：圣诞、黑五、Prime Day 等；⚠️ 大促是"人工制造的峰"不是自然季节，应**当异常清洗**而非建进季节模型
4. **大促 / 秒杀 / 断货周 → 数据清洗（削峰填谷）**：亚马逊场景最核心的适配点，平台强节奏使历史"可重复性"差；建议在「销量模拟+库存控制」表加一列"数据性质"标记（正常/促销/断货）
5. **新品（无历史）→ 线性回归 / 类似产品类比 + 德尔菲专家判断**：用同类 ASIN（同品类/价格带/流量结构）历史做相关性回归；预售期数据点极少，主张**滚动预测**尽快纠偏
6. **长尾 SKU（低频零散出单）→ 泊松分布 / 简单法则**：正态分布不适用，用"卖一补一"的幼稚预测 + 少量安全库存反而更省
7. **模型择优落地（Excel 就能做）**：周销量导出 → 分初始组/测试组 → 回测比 MSE → Solver 优化 α/β，无需离开现有工具链

### 五、指数平滑法平滑系数 α 的计算

#### 公式（来源事实，原文式 1-1 / 1-2）
```
F(t+1) = α·X(t) + (1−α)·F(t)
```
等价写法（误差修正式）：`F(t+1) = F(t) + α·(X(t) − F(t))`
- F(t+1)：下一期预测；X(t)：本期实际需求；F(t)：本期预测；α：平滑系数（0~1）

**α 的含义（两个极端）：**

| α 取值 | 行为 | 效果 |
|-------|------|------|
| α = 0 | 完全沿用上期预测（"我行我素"） | 最平稳，但永远不响应变化 |
| α = 1 | 完全用上期实际值（= 幼稚预测） | 最灵敏，但被动反应，永远慢一拍 |
| 0 < α < 1 | 实际与预测加权折中 | 在"平稳"与"响应"间取平衡 |

#### 三步择优法（来源事实）

**第 1 步：画折线图**，判断需求是"稳定 / 有波动 / 有明显趋势或季节性"。

**第 2 步：按经验值圈定范围**

| 需求历史形态 | α 经验值 |
|-------------|---------|
| 比较**稳定** | **0.05 ~ 0.2** |
| 有波动，但长期趋势无大变化 | **0.1 ~ 0.4** |
| 波动很大，明显且迅速的上升/下降趋势 | **0.6 ~ 0.8** |
| 明显上升或下降序列 | **0.6 ~ 1** |

**第 3 步：复盘回测，选 MSE 最小**——套几个相差 0.05 的 α，复盘过去 13 周，算平均均方误差，选最小者。进阶：用 Excel Solver 设"均方误差最小"自动化求最优 α。

#### 初始化与预热（来源事实）
- 初始预测 F₁ 可取上期实际值、移动平均、或随便填 0（初始值影响随迭代几何级衰减）
- **最初 9 个数据点做"预热"（初始组）**，之后约 12 期做"测试组"回测评 α
- ⚠️ 预热数据与测试数据必须分离（"避免既当裁判又当球员"）

#### 最小算例（💡 LLM 示例）
某 SKU 连续 5 周销量 `100, 120, 90, 130, 110`，令 F₁ = 100，α = 0.2：
```
F2 = 0.2×100 + 0.8×100 = 100
F3 = 0.2×120 + 0.8×100 = 104
F4 = 0.2×90  + 0.8×104 = 101.2
F5 = 0.2×130 + 0.8×101.2 = 106.96
MSE = [(120−100)² + (90−104)² + (130−101.2)² + (110−106.96)²] / 4 ≈ 358.7
```
再对 α = 0.3、0.4 各算一遍，选 MSE 最小者。实际业务用 13 周数据回测更可靠。

### 六、给 SOP 的最小改动路径（💡 LLM 推断）

不推倒重来，只改三处：

1. **【控制日销】字段升级**：`基准预测（模型）+ 推广增量（判断）`，模型出底线，推广只对"大促、断货、放量"这些历史里没有的增量做调整——正是"从数据开始，由判断结束"
2. **加一列"数据性质"**：在销量表里标记正常/促销/断货/清仓，把"削峰填谷"做成可追溯动作
3. **按 SKU 分流**：稳定款用指数平滑、爬坡款用霍尔特、季节款用温特、长尾款用简单法则——对应刘宝红"差异化对待，一刀切不是精细化管理"
