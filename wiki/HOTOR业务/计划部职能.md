# 计划部职能

> **状态**：unreviewed
> **最后更新**：2026-10-28
> **来源**：[[raw/知识文件归档/HOTOR业务/跨境电商公司业务架构与计划部职能介绍]]（负责人向计划部新人介绍，语音转写未校读）
> **这是计划岗新人的方向说明**：哪些内容块属于计划核心、哪些是历史遗留的运营支持（未来不会让新人负责）。

## 核心要点

- **计划部脱胎于事业部**：去年（2025）7–8 月正式独立成立，起初按"对接事业部"划分 → 现在按**品类**划分（车载/箱包/宠物/收纳五金…），逐步向供应链迁移
- **计划核心 = 补货计划**：需求计划（运营销售预测）→ 采购计划；另一分支 发货计划 → 提货计划 → 错货计划 → 物流计划 → 入库计划
- **跨境电商的库存管理全部压在计划**（无自有工厂/仓库），占比高于工厂型企业
- **三个大内容块**：库存管理 / 计划 / 交付，衍生协同性的风险管理
- **运营支持是历史遗留**（建单、店铺检查、欧洲合规），本质属运营/客服，新人只做了解、不负责

## 详细内容

### 1. 由来与组织演变

（来源：同前 33:12–35:05）

- 最早开发/推广/计划都以**事业部**为主，去年（2025）7–8 月正式成立计划部并单独脱离
- 成立初期仍按"对接事业部"来分工
- 这一年梳理后，逐步改为**按品类**划分（车载系列、箱包系列、宠物系列、收纳/五金收纳系列……），因为计划逐渐往供应链迁移，按品类分更利于从供应链整体看问题
- **例外**：多平台（未来事业部）业务复杂，单独设计划，不按品类走

### 2. 工作内容块

（来源：同前 37:16–48:39）

#### 2.1 运营支持（历史遗留，非新人方向）

本质属于运营/销售/客服，因"过去拖得太远"暂挂在计划，后续要移出（转运营手册）：

| 内容                | 说明                                                  |
| ----------------- | --------------------------------------------------- |
| 新品建单 / listing 建单 | 即"建链接"，本质是运营支持                                      |
| 店铺检查              | 店铺合规检查：付款/账号异常、链接被查/异常下架等，找对应负责人处理                  |
| 欧洲合规              | 产品合规（电器需 CE/FCC 等认证）+ 税务合规，本质属运营+财务+计划三块，运营接不住才给了计划 |

> 📌 负责人明确：新人方向**不是**运营支持，只简单了解操作即可，后面不会让你负责。

#### 2.2 库存管理

- **全量库存管理**，挂在计划的占比高于工厂型企业
- 工厂型企业会拆分：主计划、生产计划、物料计划（PC/PP/PM），且有独立采购、仓储中心，把管理分摊到各环节
- 跨境电商（尤其本公司）**没有自己的工厂和仓库**，库存管理一般都放在计划

#### 2.3 计划（核心大点 = 补货计划）

一条主线 + 一条分支：

```
运营销售预测 → 需求计划 → 采购计划
                 └→ 发货计划 → 提货计划（挂采购端，对应提货时间）
                              → 错货计划 → 物流计划 → 入库计划
```

- 提货计划对应"从工厂提货的时间"，需与发货相匹配
- **大点在前端的补货计划**：前端做好了，后面都相对好配合；常要"搭建模型/体系"
- 错货计划是为处理补货而设置的对应规则

#### 2.4 交付（计划衍生的环节管理）

按**环节**拆分管理，每个环节有对应的人/流程处理异常与要求：

- 生产交付环节（要求工厂有相对稳定的交期，不能今天 3 天提货、明天 30 天）
- 物流/货运环节
- 上架环节

#### 2.5 风险管理（协同）

- 交付为主管理大风险（如货运风险），但风险往往跨环节（还涉及采购、运营），需要向下协同
- 属衍生内容，目前与交付等大块并列

### 3. 协作部门与 KPI 分工

（来源：同前 49:36–51:18）

| 部门 | 负责 | KPI 偏向 |
|------|------|---------|
| 运营（上游） | 给需求（销售预测） | — |
| **计划** | 环节的**时间与异常**（在乎时效） | 交付率、准时率、及时率 |
| 采购（下游） | 合同、发票、供应商管理（内有"供应商管理"岗） | 及时/准确率 + 供应商管理指标 |
| 物流部 | 报关清关、货运 | — |
| 平台 | 入库 | — |

> 📌 关键区分：**计划在乎时间，采购在乎管理**。

### 4. 合规相关

（来源：同前 51:24–52:39）

- 公司从**两年前起走全合规路线**（此前有刷单等历史操作）
- 报关抬头用公司自己抬头；已弃用"双清包税"，自行申报缴税（含美线）
- **透明计划 = 防伪标签，一物一码**，用于防跟卖/防伪仿清销；标签贴箱，亚马逊扫码即入库，同一码不可重复入库，与 FNSKU 同一环节管理，因此挂在计划 + 采购协同管理

### 5. SKU 编号体系（口述辨析）

（来源：同前 53:12–56:20）

- 从大到小：**SPU → SKU → MSKU → ASIN → FNSKU → 透明计划码**
- **SKU** = 公司内部编码；**MSKU** = 亚马逊平台命名（一个 SKU 可建多个 MSKU，但链接通常只有一条）
- **ASIN** = 商品链接（各平台有各自的命名方式）
- **FNSKU** = 亚马逊仓储端识别库存的单位（库存标签）
- **透明计划码** = 比 FNSKU 更小一级，一物一码（FNSKU 可同批次贴同码，透明计划每件贴不同码）
- **关联动作**：在 ERP 上把内部 SKU 与后台 MSKU 配对关联（类比"人名 vs 身份证号"）
