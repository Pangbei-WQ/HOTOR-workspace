# S&OP 产销协同体系搭建方案

> **状态**：unreviewed
> **最后更新**：2026-10-30
> **来源**：刘宝红《供应链的三道防线》《采购与供应链管理》（S&OP 定义与方法论）+ [[wiki/HOTOR业务/会议记录/计划岗1v1-库容管理与试用期培养规划-2026-10-30]]（导师提出的 S&OP 设想）+ 公司现有计划 SOP
> **性质**：问答回写。用户问「S&OP 具体解释 + 结合公司 SOP 怎么搭」的综合分析，搭建路径部分为 LLM 推断，待人工审核。

## 核心要点

- **S&OP = Sales & Operations Planning（销售与运营计划）**，核心目标是制定**「同一个计划」**、消除「多重预测」（各职能各拍一个数）。
- **运行方式一句话：从数据开始，由判断结束**——计划端做数据基准，销售/推广端做判断调整，前后端叠加出「错得最少的那个预测」，全公司围着它转。
- **它是集成供应链（ISC）的核心**；S&OP 的核心又是**需求计划**。
- **需求预测 ≠ 需求计划**：预测是「客户想买多少」，计划是「兼顾产能/供应商/资金约束后平滑过的需求」（限制性预测）。
- **公司缺口**：现在需求 = 推广端销量预演直接等于需求（「从判断开始」，缺「从数据开始」的基准）；推广日历/发货/物流数据在谷歌表未进系统。
- **搭建路径（四步）**：① 立会（月度主会 + 双周滚动，先求信息对称）→ ② 需求计划化（计划做基准 + 推广出增量）→ ③ 数据上系统（修领星三大断点）→ ④ 补货模型 + ABC-XYZ 分级。

## 详细内容

### 1. S&OP 是什么（来源事实，刘宝红）

- **定义**：公司内部的跨职能协同机制，整合营销、市场、产品管理、供应链等职能，有效对接业务与运营，**制定「同一个计划」**，作为供应链协同的基础，围绕同一个预测运作（来源：[[raw/知识文件归档/供应链管理-刘宝红/1、《采购与供应链管理：一个实践者的角度（第4版）》2024年]]）。
- **本质**：从数据开始，由判断结束——制定一个「准确度最高的错误的预测」。
- **定位**：企业两大主干流程是 IPD（集成产品开发，0→1）与 ISC（集成供应链，1→N）；**ISC 的核心是 S&OP，S&OP 的核心是需求计划**（来源：《供应链的三道防线》）。
- **关键区分**：
  - **需求预测** = 客户需求，不考虑供应能力（「想吃两碗饭的需求，跟你有没有两碗饭没关系」）。
  - **需求计划** = 兼顾供应能力平滑后的需求（限制性预测），力求总体效益最大化。**这就是要有 S&OP 的原因**（来源：《供应链的三道防线》）。
- **消除信息不对称 = 拿信息换库存**：供应链上的波峰波谷，要么用库存/产能填，要么拿信息填平——信息成本更低（来源：《采购与供应链管理》）。
- **节奏**：正规做法**一个月一轮**（一个月的系列任务，含 14 件大事情、4 个会议），不是开一次会；期间大变动（新品/下市/大促）随时调。**快 ≠ 高效**，做到位才是目的。
- **反面教材（刘宝红警告）**：两周做一轮却做成「层层提需求」、无统一需求历史、各职能数据对不上 → 走过场，等于没做。

### 2. 公司现状对照（LLM 综合，待审核）

**已有 S&OP 的「半边」**：

- 独立计划岗、[[wiki/HOTOR业务/销量模拟与库存控制表]]（控制销量/控制库存两条线）、[[wiki/HOTOR业务/计划与供应链SOP]]（备发货两条公式 + 审批人李昆 + AWD/领星）。
- [[wiki/HOTOR业务/会议记录/计划岗1v1-库容管理与试用期培养规划-2026-10-30]] 中导师点名的春节方案、黑五/PD、季节品、异常库存——**本身就是 S&OP 的标准议题**。

**缺的关键一块**：

1. **需求是「从判断开始」**：推广端销量预演（控制销量）**直接等于需求**，跳过需求计划环节；计划端只做库存预演和公式换算。缺「从数据开始」的基准。
2. **数据没进系统**：推广日历、发货/提货/物流数据在谷歌表（领星三大断点未修），会导致 S&OP 会开成「各职能数据对不上」的走过场。

### 3. 搭建路径（LLM 推断，待审核）

**第 0 步：立会机制（导师已在做）**

- 频率：**月度主会 + 双周滚动检查**（单周频率太高，导师已提）。
- 第一次会只求**信息对称**：现有数据摆上桌，「不但提数据、还讲故事」（促销为何加量、供应商为何产能紧），数据 + 理由都记录在案（刘宝红：信息对称 + 讲故事 + 记录在案）。
- 固定议题模板：① 大促/春节日历 ② 季节品与新品 ③ 异常库存（高库存清库 / 低库存补货）④ 供应风险（产能/交期/货代）⑤ 事业部品类调整。

**第 1 步：把「预演 = 需求」升级成「需求计划」**

- 计划端做**数据基准**（历史销量 + 去噪 + 模型基线），推广端只出**判断增量**（促销/活动/竞品），会上对齐成唯一一版需求。
- 与 [[计划岗答疑纪要-2026-10-28]] 中「计划预测 + 推广判断」、[[wiki/供应链管理/SOP方法与刘宝红计划方法对比]] 的「最小改动路径」（控制日销 → 模型基线 + 推广增量）一致。

**第 2 步：数据上系统**

- 优先把推广日历、发货/提货/物流数据接进系统，修领星三大断点（预测依赖运营 / 单据操作 / 业务环节断联）。无统一数据源，S&OP 是空中楼阁。

**第 3 步：补货模型 + ABC-XYZ 分级**

- 模型 + 分级（ABC=货值贡献、XYZ=需求稳定，AX 优先保障）出来后，S&OP 才有量化底座（限制性预测），讨论从「拍数」变成「看基线 + 增量 + 约束」。

### 4. 两条红线

- **计划对库存调整负责**（1v1 已明确）；供应链/计划**可以建议改预测，但要跟推广达成共识，不能单方面改**（刘宝红：供应链可以建议调整，但需共识，而不是单方面调整）。
- **销冠调不调是推广/需求端的事**，计划不背这个锅（周例会已明确的责任切分）。
