# 销量模拟与库存控制表

> **状态**：unreviewed
> **最后更新**：2026-10-30
> **来源**：[[澳洲 _ 销量模拟+库存控制 _ 2026 - AU494WH.csv]]（澳洲站 AU494WH / ASIN B0DX27R6XG 值快照）＋[[销量模拟与库存控制表-逻辑转录]]（本 LLM 逻辑转录）

## 核心要点

- 这是计划运营岗的**核心工作底表**，[[计划与供应链SOP]] 的「盘点库存 → 确认推广计划 → 销量预估」全落在这张表上（一个 SKU 一张）
- 表格有**两条并行的库存线**：`实际在库库存`（真实 FBA 库存）与 `控制库存`（计划库存），靠 `控制销量`（推广拍的控制日销）与「入库 / 库存校准」事件各自滚动
- 三个「**供**」列是三种口径的**供货天数（可售天数）**：短历供（近30天）、长历供（近90天）、模拟历供（按控制日销）——直接对齐亚马逊「低库存水平费」的 28 天警戒线
- 表格的核心产出 `控制库存 ÷ 控制销量` 正是 SOP 两条时间公式里的「**预估售罄日期**」来源

## 详细内容

### 1. 这张表在 SOP 里的位置

（来源事实，源自 [[采购计划下单SOP]] 第二、三节）

采购计划下单 SOP 的「盘点现有库存」三步，全在这张表上操作：

1. **确认工厂生产** —— 核对对应 SKU 近期订单是否已填、已建单发货；已下单未发货即工厂生产订单
2. **盘点 FBA 库存** —— 先填清近期销量；再盘即将入库订单是否已被亚马逊接收（查 FBA 货件单号）：已接收 → 登记入库、在【实际在库库存】【控制库存】各加数量；未接收 → 计在途
3. **盘点在途库存** —— 其余已发货未入 FBA 的合计为在途

「确认推广计划及销量预估」一节则点名：销量预估用【控制库存】字段；发货/下单时点由它推出（见第 5 节）。

### 2. 两条并行的库存线（核心公式）

（来源事实，从 CSV 数值规律反向验证，见 [[销量模拟与库存控制表-逻辑转录]] 第三节）

```
实际在库库存(t) = 实际在库库存(t-1) − 总销量(t) + 入库(t)
控制库存(t)     = 控制库存(t-1)     − 控制销量(t) + 入库(t)
总销量(t)       ≈ 实际订单(t)（偶有手工 +1/+2 修正）
```

| 字段     | 含义            | 谁填/谁算   |
| ------ | ------------- | ------- |
| 实际订单   | 后台当日真实订单      | 人工逐日填   |
| 总销量    | 当日实际销量（≈实际订单） | 自动/手工微调 |
| 实际在库库存 | 真实 FBA 在库     | 公式滚动    |
| 控制销量   | 「控制日销」，计划用的日销 | 推广拍     |
| 控制库存   | 计划库存（用于预估售罄）  | 公式滚动    |

验证例：2025-07-18 记「入库190，PO250320037-2.1」→ 实际在库 179−6+190=363、控制库存 179−4+190=365，两列同加 190。

**两条线为何要分开**：`实际在库库存` 反映真相，`控制库存` 反映「按计划卖」的推演。二者会漂移，靠两类手工事件对齐：

| 事件 | 效果 |
|------|------|
| 入库（库存信息列「入库N，PO…」） | 两条线同 +N |
| 库存校准 / 调整控制库存 | 控制库存重置为后台真实数 |
| 停售 | 控制销量置 0 |
| 起售 / 涨价 | 记入促销信息列 |

> 📝 **口径补充（2026-10-30，来源：[[raw/知识文件归档/HOTOR业务/会议记录/亚马逊库容管理与计划岗试用期培养规划/原文_亚马逊库容管理与计划岗试用期培养规划]]，未校读）**：导师确认「控制销量 = 销量域/销量预演」由**推广端**做（历史部分不改、未来可调，BD 促销时调增），**只有推广能改、计划只提建议**；「控制库存 = 库存预演」，类似 AK（领星）补货建议；目前预演**直接等于需求**（跳过「需求计划」环节）。即本表「控制日销」是销量预演落表字段、「控制库存」是库存预演结果。

### 3. 三个「供」列：供货天数（可售天数）

> 💡 **LLM 推断（未验证）**：以下「供 = 供货天数」为推断，依据两条交叉印证，精确公式需以原 Google 表公式为准。

「供」= **供货天数**，即「当前库存还能卖多少天」。三列对应三种日销口径：

| 列 | 口径 | 对应亚马逊概念 |
|----|------|----------------|
| 短历供 | 库存 ÷ 短期（近 30 天）历史日均 | 亚马逊「短期历史供货天数（过去30天）」 |
| 长历供 | 库存 ÷ 长期（近 90 天）历史日均 | 亚马逊「长期历史供货天数（过去90天）」 |
| 模拟历供 | 库存 ÷ 模拟（控制）日销 | 计划岗自用「按控制日销还能卖几天」 |

**推断依据**：
1. [[亚马逊相关费用介绍]] 明确：低库存水平费在「短期（30天）/长期（90天）历史供货天数」都 < 28 天才收。三列命名「短/长/模拟 + 供」与此强对应。
2. CSV 数值行为：2026-11 起实际销量归零后，分母（历史日均）趋 0，供货天数爆炸——`短历供` 11-24 冲 3270 后因 30 天窗口归零变空，`长历供` 因 90 天窗口尚存销量、12-26 才冲 6758。正是「库存 ÷ 历史日均」的数学特征。

**用途**：`短历供/长历供` 逼近 **28 天**就要警惕「低库存水平费」；`模拟历供` 是计划岗自己的倒计时，稳态下每天约 −1，用来定「预估售罄日期」。

### 4. 表格的日常用法（操作流）

（综合 [[采购计划下单SOP]] + 数据规律，日常节奏为 LLM 推断）

1. **每日**：填当日「实际订单」→ 总销量、实际在库库存自动滚动
2. **推广拍**：设定「控制销量」（控制日销）→ 控制库存逐日递减，得出「预估售罄日期」
3. **看盘**：盯三个「供」列——短/长历供逼近 28 天（低库存费警戒）、模拟历供还剩几天（决定何时下单）
4. **入库时**：核对 FBA 货件单号确认已接收 → 在库存信息列登记「入库N，PO…」→ 两条库存线同加
5. **定期**：做「库存校准」把控制库存对齐后台真实值，避免计划库存越滚越偏
6. **节点**：停售/起售/涨价记入促销信息列

### 5. 与采购计划下单 SOP 公式的对接

（来源事实，SOP 原文公式）

表格的「控制库存 / 控制销量」直接喂给 SOP 的备发货大逻辑：

```
预估售罄日期 ≈ 今天 + 控制库存 ÷ 控制销量   （= 模拟历供的概念）
发货时间点    = 预估售罄日期 − 安全库存时间(通常35天) − 货运周期
下单时间点    = 预估售罄日期 − 安全库存时间 − 货运周期 − 工厂生产时间
补货数量      = 补货频次(7天或14天，通常14天) × 控制日销(控制销量)
```

一句话串起来：**表格算出「还能卖几天 / 该卖多快」，SOP 公式把「天数」换算成「哪天发货、哪天下单、下多少」**，最后落 AK 采购计划单据审批。
