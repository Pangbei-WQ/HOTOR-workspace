# 计划岗每周盘库与下单发货实操流程

> **状态**：unreviewed
> **最后更新**：2026-11-03
> **来源**：[[raw/知识文件归档/Daily/2026-11-03]]（庞贝本人实操笔记，本文是其整理版）；术语口径经 [[wiki/HOTOR业务/下单盘点工具表字段字典]]、[[计划与供应链SOP]] 补注

## 核心要点

- **每周三件事串成一条线**：① 盘库（销控表更新入库）→ ② 核对（下单盘点工具表审核表三闸）→ ③ 下单发货（工具表刷数 → 人工调 → 转填审批表），**周二下班前**交审批。
- **决策一句话**：可售天数 =（库存 + 在途预入）÷ 日均控制销量；**跌破安全库存天数才下单/发货**。触发补货的往往不是「本周不够」而是「下周会跌破」——因为补货间隔固定 14 天。
- **表不是人算的**：下单盘点工具表自动刷出参考下单量/发货量，人的活是**经验调整**——对照控销 vs 实际销量的差距、运营是否调控销，判断参考值是否可取。
- **发货口径的坑**：发货模块的可售天数**不算本周这批发货量**（本周发的货下周才回流进分子），漏填「预入」会让下周连续误触发发货。
- **易混词**：核对表的「截单」（库存被砍）≠ 脚本里的「结单」（已安排发货未实际发）。

## 详细内容

### 一、库存盘点（销控表更新入库）

> **销控表** = [[wiki/HOTOR业务/销量模拟与库存控制表]]，一 SKU 一张的计划底表：`控制销量`（推广拍的日销）+ `控制库存`（计划库存）两条线各自滚动。

每周开始，在**销控表**中更新每个 SKU 的**上周入库**情况。分三步：

**1. 更新库存查询表的数据**

- 先更新**库存查询表**的库存数据，数据来源于**领星**（AK，ERP），下载模板待领取。
- ⚠️ 本表口径在 [[wiki/HOTOR业务/下单盘点工具表字段字典]] 未覆盖，仅见于日记，待补口径。

**2. 查询入库情况并回填销控表**

把上周的**预入**（还没入 FBA、预计将来入库的量）复制到库存查询表的「查询列」做查询：

- **有入库** → 把具体信息贴回销控表中**上周一到周五**的任意格子（表示已入 FBA）。
- **仍是预入** → 把信息贴到**下周的时间**（表示最近可能入库）。
- 两种情况**都要查询**、别漏。

**3. 跑脚本同步到下单盘点工具表**

库存更新完后**运行脚本**，把数据同步到**下单盘点工具表**，进入审核环节。

**注意事项（踩过的坑）：**

1. **填写方式**：用「复制 → 删除原信息 → 粘贴信息到新格子」，因为谷歌表公式复制的特性（直接改会破坏公式引用）。
2. **时间格位**：销控表每周库存信息以**上周日到本周六**的起始顺序关联到其他表格，所以入库信息一般填在**上周的周一到周五**格子，确保所有入库都能被正常抓取。
3. **拆单发货**的库存要**另外补充**（脚本不拆单，见 [[wiki/HOTOR业务/会议记录/供应链库存盘点与补货流程培训-2026-11-02]]）。
4. **查询时间要对**：库存查询表的更新查询时间是**每周周一**，查询公式用这个时间去找入库时间、直接影响结果。例：周一 11.2 查询，查询时间设 11.2 → 正确；若周二 11.3 才查，默认时间会变成 11.3，**要改回 11.2**，否则查询结果不准。

### 二、库存盘点数据确认（审核表核对数据）

盘点完后，在**下单盘点工具表 → 子表「审核表核对数据」**中核对每个 SKU **上下两周**的数据是否有误，一般错误会**报红**提醒。

主要核对三个字段：**待生产 / 截单 / 在途**（三道守恒闸，逻辑见 [[wiki/HOTOR业务/下单盘点工具表字段字典]] 05 审批表核对）：

| 字段 | 含义（字典口径） | 对平标准 |
|---|---|---|
| 待生产 | 生产池滚动衔接：预期本周待生产 = 上周待生产 + 上周可下单 − 上周可发货 | 差值 = 0（否则漏登记新下单 / 截单没记录） |
| 截单 | 库存池缩水侦测：一周内消失的量 ÷ 实际日销折成天数 | ≈ 7 天（明显大于 7 天 ≈ 被截单砍掉） |
| 在途 | 在途池滚动衔接：预期本周在途 = 上周在途 + 上周可发货 − FBA 增量 − 日销×7 | 差值 = 0（否则海运池不平） |

> ⚠️ **易混**：这里的「截单」是核对表字段（库存被砍、去向不明），与脚本更新时写的「**结单**」是两个词——「结单」= 提前三周安排的发货计划、数据上记为已发货（实际本周才发走），见 [[wiki/HOTOR业务/会议记录/库存表更新规范与脚本操作培训-2026-11-03]]。

### 三、计划下单与发货计划

> **涉及表格**：下单盘点工具表 + 发货/采购计划审批表
> **时间卡点**：**周二下班前**提交

**1. 定位类目审批表**

每个类目都有对应的**审批表**，表名是具体 **SPU**，表内有该 SPU 所属的 SKU，能看到这些 SKU **历史周**的下单和发货记录；其中控销和库存数据直接来源于前面的**销控表**。

**2. 刷出下单发货数据**

把这些 SKU 复制粘贴到**下单盘点工具表 → 子表「下单发货」**，能刷出 SKU 对应的采购、发货信息（该子表是工具表核心引擎，逻辑见 [[wiki/HOTOR业务/下单盘点工具表字段字典]] 01 下单发货）。

**3. 人工判断与经验调整**

信息出来后，根据**实际销量 vs 控制销量**的差距，人工判断表格给出的参考下单量、参考发货量是否可取，做经验调整：

**3.1 下单判断（看本周/下周可售天数）**

- 参考因素：**本周可售天数** + **下周可售天数**（两个都基于控制库存计算）。
- 触发逻辑：因为有**安全库存**（亚马逊最小库存天数）+ **下单间隔 14 天**，本周不用下单的 SKU，到下周库存水位可能就跌破安全库存天数了。所以**一般触发补货的是「下周可售天数」跌破安全库存水位的 SKU**。

> 📌 字典公式对应：本周可售天数 = `S 列` =（到货周预测库存 + 预入在途）÷ 该周日均控销；下周可售天数 = `V 列`（同口径挪到 +7 天）；下单量 = `W 列` = `IF(V < 安全库存天数, 未来14天控销按MOQ取整, 0)`——**只有下周可售天数跌破安全库存才不为 0**。补货间隔 `M 列` 硬编码 14 天。

**3.2 发货判断（看到货周、不算当前批）**

- 判断因素类似，另外需考虑**发货周是否有已完成的库存量可发**。
- 同样要对照**控销 vs 实际销量的差距**、以及**运营是否有调整控销的计划**，再人工调整发货计划的数量。
- 关键口径：发货模块的**库存、可售天数都不算当前计划的这批发货量**——所有在库在途库存按**发货到货那时的控销**来计算库存和可售天数。

> 📌 字典公式对应：发货侧可售天数 = `AC 列` =（发货到货周 Z 日预测库存 − 到 Z 日还没发的预入量）÷ 到货周日均控销；发货量 = `AG 列` = `IF(AC > 安全库存天数, 0, (安全天数−AC)×日均+未来14天)`。**AC 不含本周新填的计划发货量**（AC 是因、AG 是果），本周发的货下周才回流进分子——漏填预入会让下周 AC 低估、连续误触发发货、越发越多。

**4. 转填审批表**

把上面算出来的**补货数量、发货数量**转填到**发货/采购计划审批表**对应 SKU 的**预下单、预发货**中。

- **审批表操作**：每次填写前都**带公式复制新的一行**出来（保留上一行公式结构）。
- ⚠️ 权限口径：计划只填「预下单 / 预发货」；「可下单 / 可发货」由审批人写（见 [[wiki/HOTOR业务/会议记录/库存数据核对与补货下单实操培训-2026-11-03]]）。

## 术语对照

| 术语 | 解释 | 来源 |
|---|---|---|
| 销控表 | = 销量模拟+库存控制表，一 SKU 一张；控制销量 + 控制库存两线滚动 | [[wiki/HOTOR业务/销量模拟与库存控制表]] |
| 控制销量 / 控销 | 推广端拍的日均计划销量 | SOP / 字典 0 表 I 列 |
| 实际销量 | 真实日均销量 | 字典 0 表 J 列 |
| 预入 | 还没入 FBA、预计将来入库的量（日销表备注「预入N」） | 字典 + 盘库培训 |
| 待生产 | 工厂生产中、还没写发货计划的状态 | 字典 05 + 脚本培训 |
| 截单 | 核对表字段：库存池缩水侦测（消失量÷日销折天数） | 字典 05 P 列 |
| 结单 | 已安排发货、实际未发（脚本更新两列之一），≠ 截单 | 脚本培训 |
| 在途 | 已发货未入 FBA 的库存 | SOP / 字典 |
| 可售天数 |（库存 + 在途预入）÷ 日均控制销量，跌破安全库存天数才下单/发货 | 字典核心公式 |
| 安全库存天数 | SKU 对应关系 M 列手填；0 表 N 列按日销量级四档（15/20/23/30）；培训另按国家分级（美稳定35/一般30/小站25-28/店景20/18）——两个口径并存，待人工确认 | 字典 + 盘库培训 |
| MOQ / 起订量 | 最小起订量 | SOP / 字典 H 列 |
| 下单间隔 / 补货间隔 | 14 天（硬编码） | 字典 M 列 |
| 领星（AK） | ERP 系统，库存数据源 | 计划与供应链SOP |
