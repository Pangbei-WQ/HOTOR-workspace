## 核心要点

- **14 张子表不是一条串行流水线**：「下单发货」读取「0」等数据形成建议；「下单汇总」「发货汇总」各自直接读取「审批表网址」所指向的外部审批数据。「发货汇总」仅从「下单汇总」镜像审批链接清单，不是接收其采购数量。主数据使用真实子表名：SKU对应关系 / LISTING / 供应商表 / 箱率 / 工厂仓名称 / 船代(同步)；另有「审批表核对数据」「日销表网址」「临时」。
- **「下单发货」先算到货时够卖几天，再判断补多少**：下单侧为 `(Q+R)/P`，发货侧为 `(AB−AD)/AA`，两侧库存口径不同，不能共用一个「库存+在途」公式。安全库存天数来自「0」N 列的 15/20/23/30 阶梯；实际分支为 `IF(可售天数>安全天数,0,补量)`，相等时仍进入补量分支。
- **可售天数有两条口径**（两个计算器各看各的到货周）：下单口径 S 列锚 O 列（下单的货到仓那周）；发货口径 AC 列锚 Z 列（本周一+船期+发货间隔 6 天 = 发货的货到仓那周）。
- **AC 是因、AG 是果**：AC 不含本周新填的计划发货量；AG = `IF(AC>I, 0, (I−AC)×AA+AF)` 由 AC 推出，填进日销表后下周才回流进分子（已发→进 AB，未入库→留在 AD 被扣）。周循环。
- **审批表核对数据 = 三道守恒闸**：待生产池 / 在途池 / 库存总池各一道，"上周填报 + 上周动作"应能精确推出"本周填报"，推不平就报警。
- **先查日期、数量口径和抓数状态**：核对区 K1/M1 与两张汇总表 E1 各有用途；「发货汇总」I/T/W 不是同一类数量；外链结果有报错时不要当作零。其他问题见 [[#坑点 Top 5（全 13 条见 raw 存档）]]。

## 详细内容

### 引擎「下单发货」的参数区（第 2 行 = 整表时钟）

```
A2 = TODAY()-WEEKDAY(TODAY(),2)+1   → 本周一
B2 = A2+21                          → 发货日（下单后 3 周）
C2 = A2-7 / D2 = A2-1               → 销量起点 / 库存截止
E2/F2 = 人工填：过年船期影响 / 交期影响
```

### 下单口径（左半区）关键公式

| 列 | 逻辑 |
|---|---|
| N | 下单日+交期 → 归下个周一（到货周锚 O 的上游） |
| O | N+船期 → 归下个周一 = **下单的货到仓那周** |
| P | 到货周起安全库存天数内的平均控制销量（IMPORTRANGE+QUERY，剔唯一峰值防刷单） |
| Q | 到货那天（O 日）的预测库存 |
| R | 备注里日期>O 的"预入N"合计（未来在途） |
| S | **可售天数 = ROUND((Q+R)/P)** |
| W/X | 下单量(14天)=本次下单到货周连续14天控销之和；下单量(补足库存)=本周库存与安全库存差额+正常补14天销量：`IF(S>I,0,(I−S)×P+W)` |

### 发货口径（右半区）关键公式

| 列 | 逻辑 |
|---|---|
| Z | `$B$2+J4+Y4` 归周一 = **发货的货到仓那周**（整条链的时点锚） |
| AB | Z 日预测库存（QUERY 日销表 Col11） |
| AD | 发货到货周之前未入库的数量（业务口径：已发货的在途+未生产批次；公式筛选=备注含 预入/待生产、非截单、日期≤Z）→ 从预测库存中扣掉防双算 |
| AC | **可售天数 = ROUND((AB−AD)/AA)** —— 锚到货周而非发货周（发货当下仓必有货，风险在海上空档） |
| AG | `IF(AC>I, 0, (I−AC)×AA+AF)` 补足库存口径发货量 |

### 字段白话口径（业务方 2026-11-03 定稿）

| 字段 | 业务口径 |
|---|---|
| F 下单预估 / G 发货预估 | 本周下单量 / 本周计划发货 与在库在途总库存的可售天数（= 本周预下单 / 预发货的库存量 ÷ 控制日销） |
| R / U 该周后、下周后下单量 | 本周后 / 下周后还有多少到 FBA 仓的预入量（应叫「预入库量」） |
| W 下单量(14天) | 本次下单到货周的连续 14 天控销之和 |
| X 下单量(补足库存) | 本周库存与安全库存的差额 + 正常补 14 天销量 |
| AD 发货时间前未发货订单 | 发货到货周之前未入库的数量（已发货的在途） |
| AE 第一票 | 首单已发货未入库的数量 |
| AF 发货量(14天) | 到货周周一前 6 天和后 8 天的控销之和（公式区间 Z−6 ~ Z+8） |
| AG 发货量(补足库存) | 在库库存的可售天数补到安全库存 + 正常发货量 |

### 审批表核对数据 — 三道守恒闸（鞋架块 W1:AK5 为例）

同一 SKU 相邻两行做两期对账。实际日期由 K1、M1 指定（均为周日），不能写成「本周一/上周一」。快照中鞋架样例 X3=M1、X4=K1；X2 只按 SKU 排序，未显式按日期排序，因此不能保证所有同 SKU 行都新期在上；运行核对前应确认日期顺序。

| 闸 | 守恒式 | 对平标准 | 报警含义 |
|---|---|---|---|
| AH 待生产 | 本周待生产 −(上周待生产+上周可下单−上周可发货) | = 0 | 漏登记新下单 / 截单没记录 |
| AI 截单 | (上周FBA+AWD+在途+可发货 − 本周FBA+AWD+在途) ÷ 实际日销 | ≈ 7 天 | 缩水远超一周销量 = 多出的部分去向不明（截单/漏填）；日销<1 退回件数 |
| AK 在途 | 本周在途 −(上周在途+上周可发货−FBA增量−日销×7) | = 0 | 海运池不平；孤立行标"新品"，断行吐"检查" |

- **报警用于定位差异，不直接判定原因（综合判断）**：生产段取消或漏登记可能导致 AH 异常；在途取消或漏填可能导致 AK/AI 异常。销量、库存填报或其他调整也可能造成差额，不能只凭报警认定截单。
- 第四道小闸 AJ「AWD差」：仅在 X 行日期=M1 时，计算 AC 列 AWD 填报 − 外部日销数据中日期>M1 的备注「预补N」数量合计。详见下方来源链条。
- 重名陷阱：原始区 AD/AE 也叫"在途/待生产"（填报数量），核对区 AH/AK 同名但值是**对账差额**，=0 才正常。

### 审批表核对数据：来源链条与删除依赖（2026-11-06 核查）

**证据范围**：本节及后续两张汇总表说明来自 [[原件存档/下单盘点-工具表-伟卿_v1_20261106.xlsx]] 的公式静态解析，未经线上刷新验证；Y 列固定 SKU 是庞贝在本次对话确认的使用口径。页面仍为 unreviewed。

**名称约定**：内部子表使用工作簿中的真实名称。外部文件完整标题没有存储在可核实的公式中，不把「审批表」「日销表」当作已核实的文件标题；以下用「审批表网址」「日销表网址」定位，保留真实子表名示例和读取范围。各 SKU 对应不同子表名，不把示例当作所有行通用名称。

#### 鞋架区 T:AK 的跳转

| 起点 | 跳转与读取 | 去向 |
|---|---|---|
| 「审批表核对数据」Y1=鞋架 | T2 查询「审批表网址」A:C：A 列包含 Y1，返回 C 列链接、B 列子表名 | T:U；示例 U2=US4012 |
| T:U | X2 用 IMPORTRANGE 逐个读取链接中的 `'子表名'!A3:V`，REDUCE/VSTACK 纵向合并，再 QUERY | 公式设计输出 X:AG |
| Y 列固定 SKU | W2 的 VLOOKUP 用 Y 列匹配「日销表网址」B 列，返回 C 列网址；匹配不到由 IFERROR 返回空白 | W 列；第 2 行显示「链接」 |
| W 行链接 + Y 行 SKU | AJ 行公式读取该链接下 `'SKU'!A2:A` 和 `'SKU'!M2:M` | 筛日期>M1、备注含「预补」，提取 `预补(\d+)` 并求和，与 AC 列比对 |

可定位示例：T2 指向 `https://docs.google.com/spreadsheets/d/1qJkXrzgsnYm-DYlIZ3jNSwQ4PlK4LUQzozBcV4Mqi5g/edit#gid=140289004`，U2 为 `US4012`，读取 `US4012!A3:V`；W3 指向 `https://docs.google.com/spreadsheets/d/1s29WhKmbc8oFze8yGlhr6j8VzGm1P0pKDkRlzx9Xt3s/edit#gid=325117192`，Y3 为 `CA0XJ012-RB-4T`，AJ3 读取该子表的日期 A 列与备注 M 列。

| 「审批表核对数据」列 | X2 设计读取的外部源列 | 字段 |
|---|---|---|
| X | A / Col1 | 日期 |
| Y | B / Col2 | SKU；**实际使用按用户确认保留固定值，不认定为实时抓取** |
| Z | H / Col8 | 控制日销 |
| AA | I / Col9 | 实际日销 |
| AB | C / Col3 | FBA |
| AC | D / Col4 | AWD仓 |
| AD | E / Col5 | 在途 |
| AE | F / Col6 | 待生产 |
| AF | L / Col12 | 可下单 |
| AG | P / Col16 | 可发货 |

X2 的筛选：源 A 列日期=K1 或 M1；排除源 B 列包含「总库存」的行；`order by Col2` 仅按 SKU 排序。Y 列已经固定时，必须核对线上 X2 是否仍为跨 X:AG 的数组公式、或是否已拆列/转值；若它尝试覆盖固定 Y 值，会产生数组展开冲突。导出文件的 Y/Z 等格多是 `COMPUTED_VALUE` 包装或保存值，不能据此确认线上刷新状态。

AJ3 的业务拆解（原式外层带 IFERROR，异常时可能返回空白）：

```text
若 X3 = M1：
  日销备注数量 = SUM(备注中「预补」后面的数字)
  条件：日期 A > M1，备注 M 含「预补」
  AJ3 = AC3 - 日销备注数量
```

因此 Z:AG 的来源是「审批表网址」指向的外部审批数据；AH/AI/AK 在本子表内对账；AJ 额外借助「日销表网址」指向的备注做交叉核对。W 本身只提供地址，不抓销量或库存。

#### A:R 为什么不能直接删

「审批表核对数据」K1=`TODAY()-WEEKDAY(TODAY(),2)-7`，M1=`K1+7`。这两格是后续品类共用的日期参数，算出的是两个相邻周日；保存值为 2026-10-25、2026-11-01。「下单发货」A2 的本周一是另一套时钟，不能混用。

鞋架 X2、厕纸架 AQ2 等跨表抓数公式直接引用 `$K$1`、`$M$1`；AD1=K1、AF1=AD1+7，AJ 的筛选还依赖 M1。清空 A:R 会清空参数，筛选可能无结果或报错；删除整列还可能造成 `#REF!`。优先隐藏 A:R；若只清数据，保留第 1 行参数；若彻底删区，先迁移参数并修改全部依赖。只清空第 2 行以下不等于删除整列。

### 下单汇总：数据来源与公式解释

定位：真实子表「下单汇总」A1、D2、L3:AC3；以下为现存公式设计，不代表已验证实时刷新。

**这张表做什么**：D:J 是审批来源的下单结果，L:AC 把它补成采购填单信息：平台标识、工厂、箱数、仓库、采购量、日期和库存备注。K/O/AA 为分隔列。

1. **A1 建链接清单**：QUERY 查询「审批表网址」A:C，选择 A 列包含「鞋架/厕纸架/孵化/马桶架/浴室架/面包箱」的行，返回 C 列网址到 A、B 列子表名到 B。
2. **D2 拉审批结果**：按 A/B 指向的实际子表读取 `A3:V`，REDUCE/VSTACK 合并，再按 E1 指定日期筛选：`Col1=E1 AND Col12>0 AND NOT Col2 matches '.*(总库存).*'`。E1 在该文件为固定日期值 2026-10-25，不能描述成自动取本周一。
3. **L:AC 补采购字段**：把 D:J 的审批结果映射到主数据，再算箱数、采购量、日期和待填写文案。这里不直接引用「下单发货」。

| 「下单汇总」输出 | 数据来源 / 公式含义 |
|---|---|
| D 日期、E SKU、F 控制日销、G 实际日销 | 外部审批子表 A、B、H、I 列（Col1/2/8/9） |
| H 预下单、I 可下单、J 运营备注 | 外部审批子表 K、L、V 列（Col11/12/22） |
| L 国家+SPU | M 前两位 + 从 E 用 `^[A-Z]{2}([A-Z0-9]*\d+)` 提取的分组码 |
| M MSKU、N 备注 | `VLOOKUP(E,'SKU对应关系'!C:F,{3,4},0)`：匹配 C，返回 E/F |
| P SKU、Q 店铺、R FNSKU | `VLOOKUP(M,LISTING!A:F,{5,6,2},0)`：返回 LISTING 的 E/F/B 列；Q 来源确为 F 列，保留真实公式口径 |
| S 供应商(可不填) | 匹配「SKU对应关系」C，返回 I（对应工厂） |
| T 单箱数量 | 匹配「箱率」A，返回 C；匹配键为 P |
| U 箱数 | T 非空时 X/T |
| V 仓库 | 匹配「工厂仓名称」A 中的 S，返回 B |
| W 采购方 | 核查样例未发现公式，按人工填写字段处理 |
| X 计划采购量 | `CEILING(I,T)`：审批可下单量按单箱数量向上取整；不是直接复制 I |
| Y 期望到货时间 | `E1+1+ROUND((4+VLOOKUP(E,'SKU对应关系'!C:I,5,0))/7,0)*7`；交期取「SKU对应关系」G，先加 4、除 7，再四舍五入为整周；**不是 ROUNDUP 向上取整** |
| Z 备注 | 镜像 J3:J1293 |
| AB 预计到货日期 | 国家码 `LEFT(E,2)` 匹配外部真实子表「船代」B:D 的 B，返回 D 的天数，再加 Y；**直接 IMPORTRANGE 外部「船代」，没有读取本簿「船代(同步)」** |
| AC 库存填写 | X 非零用 X、X=0 用 I，拼接「预入N，PO待产生，待生产」；E 空则空白 |
| I1 / X1 | 分别 SUM(I2:I1293)、SUM(X2:X1293)，是审批数量合计与整箱采购量合计 |

AB3 外部来源地址：`https://docs.google.com/spreadsheets/d/1B01hcAzWM06laBOgSADdidS-3rb2B--DCl9ClN7JGbw/edit`，实际读取 `'船代'!B:D`。历史字典把 AB 归到「船代(同步)」、把 E1 叫本周一、把 ROUND 叫向上取整，均以本次公式核查修正。游离手算式 `35*3+504+252+245-1092` 实际位于 T1，不是 X1。

样例：第 3 行 I=1000、T=8，X=1000、U=125；若 I=1001、T=8（说明性假设），则 X=1008、U=126。快照 I1=40200、X1=40250，两个合计的 50 件差额是已保存结果，未做线上重算。

**容易混淆的字段**：E「SKU」是审批来源的匹配键；P「SKU」是通过 M「MSKU」从「LISTING」带出的标识，不要凭表头相同就认为两列可互换。N「备注」来自「SKU对应关系」，Z「备注」来自 J「运营备注」。Y 先按交期计算，AB 再加运输天数，是两个不同时间点。

说明性样例：I=1001、T=8 时，X=1008、U=126，AC 会生成 `预入1008，PO待产生，待生产`。AC 只是待填写文本，不是真实 PO 单号。

### 发货汇总：数据来源与公式解释

定位：真实子表「发货汇总」A1、D2、L3:X4。

**这张表做什么**：D:J 是审批来源的本期发货结果；L:X 补平台标识、PO 与日销备注中的批次数量，供人工对照。K/U 为分隔列。现存公式没有把这些数量自动核对成「可以直接发货」的结论。

1. **A1 只镜像网址台账**：`='下单汇总'!A1:B29756`。传过来的是链接和子表名，不是「下单汇总」I/X 的数量。
2. **D2 独立抓审批发货结果**：根据 A/B 逐个 IMPORTRANGE 外部子表 `A3:V`，合并后筛 `Col1=E1 AND Col16>0`，排除「总库存」。本表 E1 同样为固定日期值 2026-10-25，未发现与「下单汇总」E1 联动公式，更新时要分别核对。
3. **L/X 查地址，M/V 读备注**：根据 E 的 SKU 经「日销表网址」找地址；M/V 使用 L 的地址读取真实 SKU 子表的 `A3:M`，从源 M 列分别找「待生产」「截单」文本，再提取 PO、数量。X 只重复显示地址，不另抓一批数据。

| 「发货汇总」输出 | 数据来源 / 公式含义 |
|---|---|
| D 日期、E SKU、F 控制日销、G 实际日销 | 外部审批子表 A、B、H、I（Col1/2/8/9） |
| H 预发货、I 可发货、J 运营备注 | 外部审批子表 O、P、V（Col15/16/22）；I 不是从「下单汇总」拿来的 |
| I1 合计发货总数 | SUM(I2:I29756) |
| L 对应日销表、X 对应日销表 | 用 E 匹配「日销表网址」B，返回 C；找不到显示「创建日销表」；两列公式相同 |
| M 日销表数据 | 读取 L 链接中 `'E行SKU'!A3:M`，QUERY 取 Col13 非空且 **以「待生产」结尾** 的记录，INDEX 取第一条；无日期排序，不保证最新、不汇总多批次 |
| N MSKU、O 备注 | 用 E 匹配「SKU对应关系」C，返回 E/F |
| P PO单号 | M 按中文逗号「，」拆分，取第 2 段并 TRIM；不会自动删除「PO」前缀 |
| Q FNSKU、R SKU、S 店铺 | 用 N 匹配 LISTING 的 A，返回 B/E/D；**S 取 D，而「下单汇总」Q 取 F，两个位置并不一致** |
| T 下单量 | 从 M 用 `\d+` 提取第一串数字并 VALUE 转数值；通常对应「预入N」，不是 I 的可发货量 |
| V 日销表数据 | 同样从 L 指向的 SKU 子表取 M，条件为 **以「截单」结尾**，`order by Col1 desc` 后取第一条，即日期最新的匹配记录 |
| W 数量 | 从 V 提取第一串数字；不是多条截单记录之和 |

**数量对照：先分清口径，再核对差异。**

| 字段 | 回答的问题 | 不能当成什么 |
|---|---|---|
| I 可发货 | 审批允许本期发多少 | 不代表某个 PO 的订单量 |
| T 下单量 | M 抓到的那一条待生产备注写了多少 | 不代表全部待生产订单合计 |
| W 数量 | V 抓到的最新一条截单备注写了多少 | 不代表全部截单数量合计 |

说明性样例：若源备注为 `预入1000，PO123456，待生产`，M 保留原文，P 得到 `PO123456`，T 得到 1000。若另有一笔待生产订单，M/T 不会自动把两笔加起来。I 与 T 不同，应先确认本期是否拆批发货、M 是否抓到目标 PO，再判断是否有填报错误；现存公式没有自动计算 `I=T−W`。

样例 L3/E3 定位：`https://docs.google.com/spreadsheets/d/1Dp8uJdttNqoj6njFFIeUDcAgxkWT9HZu3g924SG2Xps/edit#gid=1737124268`，实际读取 `US4122BL!A3:M`。不能把这个外部文件未经核实地命名为内部知识页「销量模拟与库存控制表」。

> **使用影响（公式分析，unreviewed）**：同 SKU 多笔待生产订单时，M/P/T 只展示第一笔，不是全部待发订单；「待生产」后追加文字或把中文逗号改成英文逗号，会破坏现有筛选/拆分约定。M3、V3 及其下游 P3/T3/W3 的保存结果已为 `#REF!`，静态文件不足以判断线上是授权、源范围还是数组展开问题，不将其当作零，也不认定只是本地兼容性问题。

「下单汇总」AC 生成文本 → 人工/既有流程把文本写入「日销表网址」所指向的对应 SKU 子表 → 「发货汇总」M 再读取该文本，是业务使用链条；本工作簿公式**没有自动写回外部表**，也没有生成真实 PO 单号，文案中的「PO待产生」仍是占位。

### 坑点 Top 5（全 13 条见 raw 存档）

1. Google Sheets 跨文件抓数公式不能依赖本地 Excel 刷新；普通公式、保存值与外链刷新状态要分开看
2. 「审批表核对数据」约 636 万单元格，解压 XML 约 147MB，可能导致本地打开缓慢或失败（规模数据来自历史文本字典）
3. 「下单发货」表头与内容错位：K3「工厂」实为交期、L3「供应商」实为工厂名
4. 固定参数分散：「下单发货」M=14 天、Y=6 天、B2=A2+21；「审批表核对数据」还含 DATE(2026,8,2) 的历史校准口径
5. 文本型数字：导 Excel 后 SUM 把文本当 0，核对列静默失真
