# 发货数据异常问题讨论（2026-11-12）

> **状态**：unreviewed
> **最后更新**：2026-11-16
> **来源**：[[raw/知识文件归档/HOTOR业务/会议记录/发货数据异常问题讨论/原文_发货数据异常问题讨论-妙记逐字稿]]（飞书妙记，5 分 42 秒，所有者杨伟卿）
> **性质**：配货环节现场纠错 —— 发货量数据异常的原因、修正方法与配货后核对→锁定的收尾规范

## 核心要点

- **发货量是「直接计算、不取整」**，所以会出现 `3804`、`5004` 这类带零头的怪数，与真实库存对不上
- **配货必须以「实际待生产数量」为参照**，不得超出实际可发数量；本次异常是没按待生产数量写，出现了实际只有 3000 套却写 3804、只有 500 套却写 1000 套的情况
- **配货完成后先核对再锁定**：核对 MSKU、透明计划、配货数量是否齐全；核对无误后执行**计划锁定**，锁定后数据才会下推采购的**提货计划**
- **系统自带的「检查」功能暂未发现实际作用**，数据准确性仍需人工逐一核对
- **T code 绑定**：下周二下班前完成，绑完即收尾

## 详细内容

### 1. 发货量异常的原因

- 发货量由系统**直接计算、没有取整**，产生了 `3804`、`5004` 这种数字
- 更严重的是**超实际库存配货**：
  - 某品实际库存只有 **3000 套**，发货量却写了 **3804**
  - 某品只剩 **500 套**，却写成了发 **1000 套**
- 根因：配货时**没看「待生产数量」**，凭感觉写了数量；批的时候也没人逐条核对

### 2. 修正要求

| 错误项 | 修正为 | 说明 |
|---|---|---|
| 3804 | **3000** | 按实际库存/待生产数量改回 |
| 1500 | **500** | 编辑条目改数量 |
| 5004 等零头 | 按实际可发数量修正 | 发货量应为「这一批实际能发多少」 |

- 异常情况需**向李坤解释**（逐字稿原话「下周自己跟李坤解释去吧」），说明为何出现数量异常

### 3. 配货后的核对清单（锁定前）

配货完成后、锁定前，逐项核对：

1. **MSKU 对不对**（逐字稿写「MSQ」，结合上下文疑为 MSKU 转写，待校读）
2. **透明计划**有没有问题
3. **配货数量**是否配齐（本次就「差 1000」要单独补）
4. 以**实际待生产数量**为参照，不超出实际可发数量

> 逐字稿原话：「这些确定了……他配货也全部都配好了，我就差 1000」——说明核对时发现缺配要单独补齐。

### 4. 锁定与收尾

- 核对无误后**直接执行「计划锁定」**，锁定完成后数据自动下推采购的**提货计划**
- 系统里有「检查」功能，但「好像没什么用」，仍需人工逐一确认
- **T code 绑定**：下周二下班前绑完（与 [[发货计划建单流程-2026-11-05]] 的「透明计划注册→绑定 T code」周二硬卡点一致）
