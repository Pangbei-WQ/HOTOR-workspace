# 透明计划相关操作流程讨论（2026-11-11）

> **状态**：unreviewed
> **最后更新**：2026-11-11
> **来源**：[[raw/知识文件归档/HOTOR业务/会议记录/透明计划相关操作流程讨论/原文_透明计划相关操作流程讨论-妙记逐字稿]]（飞书妙记，7 分 25 秒，所有者杨伟卿）
> **性质**：导师带教实操 —— 透明计划注册后「申请代码 → 绑定提货 → 状态维护」的下游衔接操作，是 [[透明计划注册操作流程与系统衔接培训-2026-11-06]] 注册流程的续篇。

## 核心要点

- **注册/申请门槛**：无账号先注册、有账号直接申请；完成 OPR 申请才能申请透明计划代码（代码申请不因 OPR 被调出而受阻，但需定期核查调出状态并重新启用）
- **运营备注 = 内部自填**（标主单/种子/变体，自我提醒用），原运营备注 = 采购单自带备注，两者不同
- **申请代码填 PO 号**（非入库必备，帮工厂区分标签贴到哪批货）→ 提交后系统生成 **PID** → 历史记录下载 CSV → 内含一一对应的 **tcode** 码
- **卖家记号 = 店铺标识**：新店铺需预估售卖店铺后填；在评论区「如何向买家」后查看；用于 OKR 填写 + 合规资料（VAT 绑定）
- **状态管理页面只做查看 + 停用/启用**；绑定提货在**发货计划页面批量操作**（全选、按发货数量绑定），不在透明计划页面
- **绑定后采购直接生成标签**，计划侧无需再传文件；**MSK 搭建完的单据整单锁定即推下游**
- **节奏卡点**：新注册须**周二下班前**完成，预留半天后台回传火家（发货计划）时间

## 详细内容

### 1. 注册与申请门槛

- 无账号主体先注册，有账号直接申请；**先申请 OPR 才能申请代码**
- 纠正口径：调出 OPR 的 ≠ 先申请再申请代码——需**定期核查是否被调出**，调出就重新开回，否则影响透明计划状态；但该状态**不影响申请透明计划代码**

### 2. 表格维护（运营备注 / PO 号）

- **运营备注列**：内部自填，标「主单 / 种子 / 变体」自我提醒；**原运营备注**是采购单自带备注
- 申请时填 **PO 号**（发货计划上的订单号）：非入库必备，仅为让工厂区分标签贴到哪批货

### 3. 代码申请与 tcode 绑定

- 提交申请后系统生成 **PID** → 用 PID 在**历史记录**下载 CSV → 文件内含一一对应的 **tcode** 码（即注册成功的码值）

### 4. 卖家记号

- 卖家记号 = 店铺标识，表格里默认预填（模板表为 Kisher 之前填好）
- **新店铺**需填该产品计划售卖店铺的卖家记号
- 查看位置：店铺评论区「如何向买家」后面那串（A 开头）
- 使用场景：**OKR 填写** + **合规资料准备（VAT 绑定）**，其他环节用得少

### 5. 状态管理与停用/启用

- 透明计划页面**只用于查看状态 + 停用/启用**，不做绑定提货
- **停用流程**：先在页面停用 → 再找**透明计划经理**取消 → 人为变回「已注册」状态
- 调出 OPR 数据前段时间刚维护过：不确定就在状态页核查，仍要继续用就重新启用

### 6. 发货计划绑定提货

- 绑定位置在**发货计划页面**（不在透明计划页面），可直接**全选批量绑定**，系统按发货数量绑定
- 先筛选透明计划商品、检查是否都有透明计划标识
- **新注册需周二下班前完成**，预留半天后台回传火家时间
- 绑定后采购端直接生成所需标签，计划侧无需再传文件
- **MSK 搭建完的单据 → 整单锁定 → 自动推下游**（周二下班前做好）
