# 库存数据核对与补货下单实操培训（2026-11-03）

> **状态**：unreviewed
> **最后更新**：2026-11-03
> **来源**：[[raw/知识文件归档/HOTOR业务/会议记录/库存数据核对与补货下单实操培训/原文_库存数据核对与补货下单实操培训]]（语音转写，未经校读，约 35 分钟）
> **性质**：计划岗新人（庞贝）入职培训 —— 带教同事讲**库存核对 + 补货下单实操**。是 [[wiki/HOTOR业务/会议记录/供应链库存盘点与补货流程培训-2026-11-02]]（周一盘库三步）的续篇。

## 核心要点

- **脚本抓不到的两种情况**：新品 ASIN 没及时填 → 数据源抓不到 → 空；有日销才带出偏差、无日销显示数量。缺的**人工预修正**，顺手把 ASIN 补上，下次就能自动更新。
- **爆红阈值**：按控销算偏差，偏差 **>3.5 天**才爆红（小偏差不处理）；新品只有一周数据、或销量低/断货导致的小偏差都不管。
- **库存核准（重要）**：AK 默认用「可用库存」，会**漏掉亚马逊预留库存**；鞋架退货影响大 → 设「库存核准页」定期校准，可用脚本跑，建议前期每周校一次。
- **审批表机制**：周二下班前提交 → 李坤周三/周四审批，**审批后覆盖公式、留备份、截图发回**；计划只填「预下单 / 预发货」，可下单/可发货是李坤写。
- **下单/发货判断**：看「可售天数 vs 安全库存天数」——低于安全库存就补；补多少结合控销 + 实际销量 + 起订量（MOQ）。
- **新品规则**：新品入库前**不返单**（除非推广特别说）；推广没写控销的要提醒补。

## 详细内容

### 一、库存核对：脚本抓不到的场景

- **新品 ASIN 未填** → 数据源抓不到这一条 → 该列空 → 人工预修正（把数据填上 + 顺手补 ASIN，下次脚本就能自动更新）。
- **被覆盖/漏贴**：有日销时显示偏差数字、无日销显示数量；偏差是根据「控销」算的本周大概偏差值，用来发现「有没有漏掉一整票」。
- **爆红规则**：控销偏差 **>3.5 天**才爆红（例：偏差 1700 但相对销量基数不算多 → 不爆红）；新品只有一周数据、销量低/断货状态的小偏差 → 暂不处理。

### 二、库存核准：可用库存 vs FBA 库存

- **问题**：表格默认用「可用库存」，但亚马逊会把部分货**预留**（reserve），这部分在 AK 里不算可用库存，于是被忽视。
- **场景**：退货影响（销量大的品退货影响可能上千）、预留释放（如上周 0329 有预留、慢慢释放后影响库存）→ 需要定期修正。
- **做法**：设「库存核准页」，一段时间核准一次（鞋架退货多，建议前期每周校一次），导出后用脚本跑、把校准数据贴回；可考虑把字段从「可用库存」改成「FBA 库存」。
- **前提**：调库存前先确保自己更新没问题；是后台库存偏差才能直接调，若是自己更新错了要先找出来。
- **备注给审批人**：人为修正过的库存要在表上备注「以修正后数量为准、之前数据错误」，否则李坤会问。

### 三、审批表填写与节奏

- **节奏**：周二下班前提交审批 → 李坤周三/周四审批 → 他把公式覆盖掉、留结果备份、截图发回；计划下次填之前把公式留出来（Ctrl+C 向上插入 Ctrl+V）。
- **计划只填「预下单 / 预发货」**（周二前填）；「可下单 / 可发货」是李坤写的。
- **填写依据**：用审批表数据核对——它抓销控表（控销、到货周可售天数）判断是否要补。

### 四、补货下单判断逻辑

- **判断**：看两个数——「到货周可售天数」（销控表算的）vs「自己设的安全库存天数」。低于安全库存 → 要下单/发货。
- **补多少**：参考控销 + 实际销量 + MOQ。控销 66、实际也到 66 = 符合预期 → 按控销补（如直接补 1000）；近期销量低于控销 → 下调；小站点就按起订量补、别补多。
- **交期与发货方式**：4122 系列交期 **20 天** = 下单即发货（本周下单、三周后 11/23 就能出，直接安排发货）；非 20 天交期的要分开写（下单、发货分开）。
- **紧急判断**：可售天数低到危险 → 加快发货渠道（快船）；没到危险 → 按正常发货方式。判断依据是「到货周可售天数」而非拍脑袋。
- **新品**：入库前不返单（除非推广特别说提前返单）；推广没写控销 → 提醒补。
- 字段：交期（下完单到工厂交那周）、船期（发货时间 + 船带时间）、MOQ（起订量）。
