# FTD补货流程及SKU规则讲解（2026-11-02）

> **状态**：unreviewed
> **最后更新**：2026-11-02
> **来源**：[[raw/知识文件归档/HOTOR业务/会议记录/FTD补货流程及SKU规则讲解/原文_FTD补货流程及SKU规则讲解-妙记逐字稿]]（飞书妙记，50 分 16 秒，杨伟卿主讲）
> **性质**：计划岗新人（庞贝）入职培训 —— 导师讲解 FTD 全链路、领星单据流转与新旧 SKU 编码规则

## 核心要点

- **FTD = Forecast to Deliver**：从销售预测到最终交付的全链路。当前核心交付场景是**备货至亚马逊、沃尔玛等平台仓**；多平台一件代发占比很小
- **FTD 主要对应「二次采购」（常规补货）**；新品段走 **GTM** 大流程（前端新品开发 → 下单），两者是不同的大环节
- **库存盘点盘三个环节段**：①在途是否入库 ②在产订单是否转在途 ③上周新增的在产/采购订单
- **「已审待发」是本库库存口径的关键新概念**：发货计划提前 14–21 天输出并审批、但货未实际发出。此前为方便维护与实际在途合并统称「在途」，现在要**严格区分**两段
- **采发一条线是现状、采发分离是方向**：供应商交期 21–30 天与发货计划提前 14–21 天太接近，被迫同步制定；未来自有集货仓建成后推行分离（邵青统筹）
- **新 SKU 有编码规则、旧 SKU 没有**：新 SKU = 品牌 + 大类缩写 + 二级品类 + SPU + 核心三属性；旧 SKU 存量不新增、靠映射表过渡
- 会上布置 4 条待办：看细化流程文档、后续细说 GTM、**整理旧→新 SKU 映射表**、实操全流程并整理问题

## 详细内容

### 1. FTD 全链路分段（口径以本次逐字稿为准）

```
销量预测(运营) ──直接流转──► 计划运营（无独立需求提出/评审环节）
   │
   ├─ 新品是否创建 Listing ──► 现归【运营支持】判断（此前归计划运营，权责已调整）
   ▼
库存盘点（三环节段 + 已审待发/实际在途区分）
   ▼
采购计划（物流周期 + 供应商交期 + 推广特殊需求）──► 李坤审批
   ▼
下单规范评审（导师本人负责：数量、下单方式合规性）
   ▼
执行采购（链接维度 → 供应商维度，生成采购单；确认交期/价格；签合同电子签存档）
   ▼
发货计划（与采购计划同步制定 → 供应商确认可提货 → 调整发货方式）
   ▼
物流（创建货件 → 凑柜初排 → 货代报价（提前约1周）→ 报关清关资料 → 外箱标同步）
   ▼
质检（品控组管新品标准 / 质检组驻外抽检常规批次）──► 发货到货代
   ▼
FBA 入库跟踪（FTD 的 D = deliver 到海外仓点，后续衍生异常处理环节）
```

### 2. 库存盘点的口径重点：已审待发 ≠ 实际在途

- **业务背景**：发货计划需**提前 14–21 天**输出，审批/确认同样提前，于是存在「已审批确认、尚未实际发出」的环节段 —— 即 **已审待发**。此时工厂可能甚至还没生产、或已生产放着
- **变动率**：初版发货计划基本不动，约 **1%–5%**（百条变一条都算多）；李坤审批时的调整约 **5%–10%**，主要出于链接布局、利润等考虑
- **实际在途**可细分为：工厂 → 货代仓 → 海上运输 → 末端配送（美国走「伟城」，转写存疑）→ FBA 仓
- **历史遗留**：以前系统里没有这段数据、靠手工维护，为方便把两段合并都叫「在途」；现在要严格拆开，否则审批会重复审、发货会重复发

### 3. 审批与权责（现状 → 未来）

| 事项 | 现状 | 未来方向 |
|------|------|---------|
| 发货计划/采购计划审批 | **李坤**（计划最高审批人，兼营销中心最高负责人） | 补货逻辑成熟后转「**系统 + 核心负责人确认**」，李坤回归营销中心只做大方向对齐 |
| 下单规范评审 | 导师（杨伟卿）本人：确认数量、下单方式合规 | — |
| 新品是否创建 Listing | **运营支持**（此前归计划运营，已调整权责） | — |
| 配货 | **计划**做实物库存的分配决策；**执行采购**做系统端单据配货操作 | — |

- 未通过审批的采购计划，若涉及推广加码被驳回（如 1000 套想加到 10000 套被认为风险大），需推广**重新调整控销**后再来
- 补货计划的大调整理论上要**与推广共识**

### 4. 执行采购环节

- **维度转换**：计划端按**链接维度**输出采购需求 → 执行采购按**供应商维度**合并生成正式采购单（要给供应商具体合同）
- **信息确认**：交期、价格（绝大多数无变动；产品变更成本升降、大促如 PD 找供应商做特价时会有小幅调整）
- **产能异常**：供应商反馈产能不足 → 执行采购回传可执行方案 → 计划运营评估是否接受调整（延迟 3–5 天一般可接受）
- **合同**：采购单审批通过后签采购合同存档，当前多用**电子签**提效

### 5. 采发一条线 vs 采发分离

- **为什么现在一条线**：供应商交期普遍 **21–30 天**，发货计划提前 **14–21 天**输出，两个时效太接近，无法明确区隔「先采后发」，所以做采购计划时经常同步做发货计划
- **历史命名**：内部叫「采购发货表」，但本质是**发货计划表**（以前跟着订单走沿用了旧名）
- **发货方式调整**：结合供应商反馈的可提货情况 —— 产线出问题时可改发快船等其它货运方式
- **采发分离的目标态**：自有仓库建成后，工厂按交期生产完送自有仓 → 发货时盘**库内库存** → 不够再形成采购需求。同时支撑：
  - **常备库存**（存放周期约一个季度）
  - **多平台小批量订单的调拨**（多平台起订量小，需要库存概念做调货）
- **集货仓项目**：目前在讨论处理形式、找合适仓库，**邵青**统筹推进

### 6. 质检分工：品控组 vs 质检组

| 小组 | 职责 | 细节 |
|------|------|------|
| **品控组** | 新品开发阶段的质量标准制定与检测 | 要求高，按品类差异化：化学除湿类看成分；五金类看管材、防锈工艺（覆膜 / 镀锌 / 刷漆） |
| **质检组** | 常规批次抽检 | 尺寸（长宽高）符合性 + 简单抽检（跌落风险、螺丝吻合等）；**长期驻外**：广东（广州/中山/佛山）+ 浙江（宁波/上海/义乌/金华），出差各厂，出质检排期 |

- 质检发现问题 → **二次批退**流程 → 批退代表延期 → 发货计划与发货方式要相应调整（急货换发货方式保时效）

### 7. 领星（AK）单据流转规则

```
采购计划 ──► 采购单 ──推送──► 质检单 ──质检通过──► 入库单 ──► 虚拟工厂仓库存 +
                                                                    │
发货环节：发货单 ──► 配货（执行采购）──► 出库（工厂仓扣减）──► 物流 ──► FBA 仓入库
```

- 系统仓库用的是**虚拟工厂仓**（领星帮助文档已有说明）
- **配货规则**：前端采购单库存细化到 **FNSKU** 直接按仓点配；只到 SKU 会跳出条码确认环节
- **库存概念很短**：基本「当周发当周入库」，当周货好当周发，库存概念几乎被忽略 —— 这是后续要补的课（见第 5 节常备库存/集货仓）
- **单据规范的战略意义**（导师原话要义）：现在很多环节数据缺失或靠人工维护，**要形成自己的补货模型，本质上要先规范单据操作**，才能形成标准化数据 —— 与 [[计划与供应链SOP]] 第 7 节「领星补货模型未启用三大断点」互相印证

### 8. 维度差异：链接维度 → FNSKU 维度

- 采购审批环节（一直到坤哥审批）都按**链接维度**统计
- 最终发货计划必须细化到 **FNSKU**：发到哪个店铺、哪个 FNSKU、多平台还要分仓分配（A 仓 100 个、B 仓 80 个）

### 9. GTM 与 FTD 的关系

- **GTM**：新品段大流程，从前端新品开发到下单；新品没有历史数据，先发多少以前端输出为主，涉及排插、市场打磨、开模打样等采购端环节
- **FTD**：主要覆盖**二次采购 / 常规补货**
- 导师明确：前期先掌握 FTD，GTM 后续再细说（对应待办 2）

### 10. SKU / MSKU 编码规范

**层级**：SPU → SKU → MSKU（MSKU 与 FNSKU 一一对应，实际发货以 MSKU 操作）

**新 SKU 规则**（内部规则）：

```
SKU  = 品牌 + 大类缩写 + 二级品类编码 + SPU编号 + 核心三属性
例：  KTH     H(home)   二级品类(如鞋架)    435      数量/颜色/尺寸等三属性
```

- **SPU**：三位数编号为主（如 435）
- **二级品类**：按内部品类写（历史上有按英文/中文写的不一致，正常按中文）
- **三属性**：只取核心三个属性 —— 属性差异大到三个都装不下，就该算新 SPU/新产品了；属性顺序系统有固定排序规则，不会乱

**新 MSKU 规则**：

```
MSKU = 国家 + 店铺公司简称 + SKU + 版本/额外编号
```

- 国家维度在前（因为最终发到具体站点）；「店铺公司简称」是店铺所属公司的简称

**旧 SKU 现状**（无规则，存量不新增）：

- 命名混乱：如 `417`（纯 SPU 式）、`US494`、`D1494`（同一产品国家码重复出现）；属性分隔符不统一（点BL / 杠BL），甚至把供应商写进去
- **存量处理**：旧 SKU/旧 MSKU 不淘汰、日常维护、**绝不新增**
- **过渡方案**：不做全量数据迁移 —— 全改是大工程（SKU → 价格维护 → 下单 → MSKU → 发货全链要跟着改）；新规则只约束**新增**（如新建跟卖 MSKU 必须按新规则）
- **旧 SKU 进新体系的方式**：新建 MSKU 时，把旧 SKU 原样放进新结构中间（国家 + 店铺 + [旧SKU] + 供应商编码如 S0001 + 版本/需求），旧 SKU 里国家写几遍、属性写多乱都不用管，保证中间是 SKU 即可
- **落地抓手（本次待办）**：整理**旧 SKU → 新 SKU 映射表**，标清每次发的是哪个链接，避免混乱
