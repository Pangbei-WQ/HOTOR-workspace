# outputs/ — 成品库

> 本库第三层：**交付物**。区别于 `raw/`（原料，输入）和 `wiki/`（知识，连接）。
> 本文件是成品库的「约束先行」契约，改动需说明理由并追加 `wiki/log.md`。

## 三层定位（组织形态，不是详略）

| 层 | 形态 | 回答的问题 | 谁动 |
|---|---|---|---|
| `raw/` | 原样未整理（乱、碎、重复、口语） | 我收到了什么 | 人投、LLM 只读 |
| `wiki/` | 压缩成精华（要点、关联、网络） | 我知道了什么 | LLM 维护 |
| `outputs/` | 理顺成完整（有序、可读、可执行） | 我做出了什么 | 人 + LLM 共管，`final` 人工门 |

一句话判据：**「这文件以后是查还是用」**——查进 `wiki/`，用进 `outputs/`。

## 生产逻辑

**来源：只从 `raw/` 理顺展开，不新增事实。**

- **重排**（顺序 / 分组 / 标题 / 衔接 / 去重）：随便动，**不用标**
- **新增**（判断 / 数字 / 结论 / 建议）：必须**指回 `raw/` 某处**，或标 `> 💡 LLM 推断，未审核`
- `raw/` 出新版本 / 新口径 → 对应的 outputs **重理顺**（靠 outputs 头部 `sources` 反查受影响项）

铁律两条：

1. **必须带 `sources`**：指向产出的 raw 来源，可追溯、可审计
2. **与 `wiki/` 弱关联**：outputs 不进 wiki 双链网络；wiki 页面可挂「交付物 [[outputs/xxx]]」单向指针

## 触发机制（只提醒，不自动生成）

| 类型 | 例子 | 触发 |
|---|---|---|
| 节拍型 | 周报、月度对账、例行 SOP 更新 | 到点提醒：该产出 / 更新了 |
| 事件型 | 方案、应急缺料、培训纪要 | 事件 / 指令触发 |

**提醒条件**：`raw/` 出现会推翻既有 outputs 结论的新素材（新口径 / 新版本 / 异常数据）→ 提醒「这 N 份 outputs 受影响，要不要重理顺」。生成本身始终由用户点头 / 指令触发，**不做周期自动生成**。

## 质量确认

第一判据：**照着做不返工**（正确 > 完整 > 可执行），阅读体验第二。

两道闸：

1. **AI 自检**（出 `draft` 前内置）：
   - 追溯：新增断言全有来源 / 全标推断
   - 完整：`raw/` 关键事实不漏
   - 对账：数字、口径与 `raw/` 一致
2. **人工终审**（`draft → final` 的门）：正确性、可用性、返工点——**`final` 仅人工点头**，LLM 只能产出 `draft`

## 状态机

| 状态 | 含义 | 谁能设 |
|---|---|---|
| `draft` | 草稿，还在改 | LLM |
| `final` | 终版，已定稿 | **仅人工** |
| `archived` | 已交付 / 已过时 | LLM（需在 log 说明） |

## 两类成品分治

- **复用型**（模板、SOP、检查清单）→ 长期留在主目录，反复用
- **一次性**（报告、计划、某次对账结果）→ 终版交付后进 `归档/`，不长期占据主目录

## 约定子目录（首个成品落地时按需创建）

```
outputs/
├── 模板/        # 复用型：可反复套用的模板
├── SOP/         # 复用型：标准操作流程 / 检查清单
├── 报告/        # 一次性：报告、计划、对账结果
├── 方案/        # 一次性：方案书、评估
└── 归档/        # 已交付 / 已过时的成品
```
