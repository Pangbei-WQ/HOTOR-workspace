# outputs/ — 成品库

> 本库第三层：**交付物**。区别于 `raw/`（原料，输入）和 `wiki/`（知识，连接）。
> 本文件是成品库的「约束先行」契约，改动需说明理由并追加 `wiki/log.md`。

## 三层定位

| 层 | 回答的问题 | 目的 | 谁来动 |
|---|---|---|---|
| `raw/` | 我收到了什么 | 留证 | 人投、LLM 只读 |
| `wiki/` | 我知道了什么 | 会查 | LLM 维护 |
| `outputs/` | 我做出了什么 | 会用 | 人 + LLM 共管 |

## 一句话判据

问一句：**「这文件以后是拿来查，还是拿来用？」**

- 查（沉淀成知识）→ 进 `wiki/`
- 用（交付 / 执行 / 反复套用）→ 进 `outputs/`
- 两面都占（典型如 SOP）→ `outputs/` 存**可执行版本**，`wiki/` 只存**知识要点 + 指向成品的链接**，不重复抄内容

## 生产逻辑

**从哪来（两种原料）**

- 从 `raw/` 加工：原始数据 / 资料 → 报告、计划、对账结果、方案书
- 从 `wiki/` 提炼：知识网络 → SOP、模板、检查清单、操作指南

**两条铁律**

1. **必须带 `sources`**：标注成品是从哪份 raw / 哪个 wiki 页面生产出来的，可追溯、可审计
2. **不参与 wiki 双链网络**：成品只做弱关联（来源 + 相关页面），保持知识网络干净

## 状态机

| 状态 | 含义 |
|---|---|
| `draft` | 草稿，还在改 |
| `final` | 终版，已定稿 |
| `archived` | 已交付 / 已过时 |

## 两类成品分治

- **复用型**（模板、SOP、检查清单）→ 长期留在主目录，反复用
- **一次性**（报告、计划、某次对账结果）→ 终版交付后进 `归档/`，不长期占据主目录

## 约定子目录（首个成品落地时按需创建）

```
outputs/
├── 模板/        # 复用型：可反复套用的模板
├── SOP/         # 复用型：标准操作流程 / 检查清单
├── 报告/        # 一次性：报告、计划、对账结果
├── 方案/        # 一次性：方案书、评估
└── 归档/        # 已交付 / 已过时的成品
```
