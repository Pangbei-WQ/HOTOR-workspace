# 鞋架备货逻辑核查报告（草稿）

## 先看结果与使用边界

**已核实的主线**：先把库存账做准，再确认未来控制日销；「下单发货」提供建议，人工调整后填审批；「下单汇总」「发货汇总」读取审批结果，并补采购信息、日销备注和PO。审批量、整箱采购准备量与真正已下PO/已发货是三个阶段。

**真实鞋架样例 US4122BL**：「下单汇总」I6可下单15000件，T6每箱16件，按箱率取整得 X6=15008件、U6=938箱；「发货汇总」I3可发货15000件。两个15000相同不证明同一批PO、也不证明已经发出。源文件中该SKU待生产备注报错，缺少到货周预测数据，无法独立复算最初为何建议15000件。

**两个附件可借鉴的是预测/历史双口径、差异化服务水平和分批到货模拟，不宜直接照搬文件**：已确认外链、分类错误被IFERROR掩盖、运输周期无样本等问题；样例建议20箱与已填补货0件也不是同一口径。

全文标注三类证据：来源事实（原文或单元格）、培训/用户确认（未代替代码验证）、分析建议（LLM推断，未审核）。线上访问、脚本代码、实际系统执行凭证的缺口详见BLOCKED.md。完整文件名、路径、日期与线上ID见来源台账.md。

## 1. 按个人SOP逐步走，逐步对照公司制度

主顺序来自 raw/知识文件归档/Daily/2026-11-03.md；公司制度分别来自「采购计划下单SOP.md」「发货计划SOP.md」「库存规划.md」。以下操作建议为综合判断，不表示已在源表执行。

| 顺序 | 输入与动作 | 输出/去向 | 核对与异常处理 |
|---|---|---|---|
| 0 建单关联前置检查 | 公司采购SOP要求核实AK产品SKU、后台MSKU/Listing、采购信息和关联关系 | 身份对应完整后才开始计划 | 缺映射先补主数据；个人SOP从盘库开始，不代表省略新品前置检查 |
| 1 更新库存查询 | 个人SOP写明来源领星；更新库存查询数据，并把查询日期设回本次盘库规定时点 | 供查PO/货件入库的基础数据 | 本轮未核实对应线上文件标题、ERP导出模板和字段；不能编造报告名称 |
| 2 回填入库与预入 | 用PO/货件核实已接收数量；已入库回填历史周，仍预入按新ETA移动 | 对应SKU的库存与日销子表 | 不直接覆盖公式；已入库与仍预入不可保留重复数量；部分到货按批次拆开 |
| 3 脚本同步 | 培训描述先删除相同PO旧记录，再粘贴待生产/结单数据 | 更新库存备注及相关状态 | 先核对源日期；拆单、新品缺ASIN可能漏更新；代码和确切入口尚未验证 |
| 4 两期对账 | 「审批表核对数据」把两期审批结果相对照；AJ另读预补备注 | 无法对平的SKU进入异常核对 | 看库存件数及日销折算，低日销时不要把件数误读成天数；先查登记错误再考虑库存校准 |
| 5 确认未来需求 | 推广给出产品补货后期间控制日销，结合促销、淡旺季、断货及实际销量判断 | 对应SKU未来日序列的控制销量 | 历史实际日销是校验基线，不直接等于未来预测；销售目标不自动等于需求 |
| 6 算采购/发货建议 | 「下单发货」分别算采购到货时点与发货到货时点的库存、可售天数和补量 | W/X、AF/AG等建议字段 | 先排除报错、缺参数、重复预入和不可用库存，再人工调整；不能看到建议就直接下单 |
| 7 填审批 | 个人SOP要求复制保留公式的新一行，计划填预下单/预发货 | 对应类目审批子表 | 审批人填写可下单/可发货；培训描述审批后可能覆盖公式保存结果，历史固定值并非异常本身 |
| 8 采购与物流执行 | 「下单汇总」补采购字段；公司采购SOP要求审批后在AK提交采购计划，再流转采购下PO/合同；公司发货SOP要求采购、物流确认最终计划 | PO、发货计划/出库/货件证据 | 本报告仅有表内保存值，没有最终执行凭证；公司SOP提醒AK「期望到货时间」实际为期望发货时间，别误当FBA接收日期 |
| 9 备注回流 | 将批准并确认的数量、PO、预入日期写回对应SKU记录 | 下一次盘库和补货计算的在途/待生产依据 | 模板「PO待产生」不是正式PO；状态迁移应核销旧记录而非不断新增 |

时间口径存在明确差异：个人原文有「上周日到下周六」，培训又有「周一到周六」「每周日为节点」；核对表实际用两个周日，工具引擎用本周一，不能把它们合并成一个通用截止日。操作前以当前具体公式的区间和公司确认的业务截止点核对。

## 2. 库存和预计日销以什么为标准

| 数据 | 目前可证实的标准 | 不应混淆的地方 |
|---|---|---|
| FBA库存 | 公司两份SOP要求按货件接收确认，已接收增加库存、未接收保留在途；培训[11:42]—[14:00]描述退货/预留需要校准 | 可用库存不等于FBA总库存；预留释放时间未证实时，不把全部预留当立即可售。具体ERP字段定义与快照尚缺 |
| AWD | 审批字段与FBA分列；「审批表核对数据」AJ读取日期>M1的预补备注，比较AC的AWD填报 | 不能同时计入FBA、AWD及未来预补；预补记录不是即时可售FBA |
| 实际在途 | 公司SOP定义已发货未入FBA | 已审待发/结单的内部记录可能先于实物发走；需实物状态与内部状态双标识 |
| 待生产 | 未下发货计划的生产/订单记录，培训如此描述 | 不是已经在海上的货；具体状态转换以实际订单、出库凭证为准 |
| 控制库存 | 从未来控制销量与入库记录形成的预测库存；工具Q/AB读外部Col11 | 与后台即时实存不是同一个数。两条库存线的具体源公式本轮不可访问，不拿其他SKU的反推公式冒充鞋架实测 |
| 实际日销 | 审批取外部I列（Col9）；工具E比较上周实际Col7与控制Col10之和 | 当前鞋架源表实际日销统计窗口未能独立核实；不能凭名称宣称一定是7/30天 |
| 控制日销 | 公司「库存规划」明确为推广对补货后周期的销量预测，考虑活动及产品变化；工具读每日Col10 | 应是分日期需求，不是一格销售目标长期不变；工具采购P和发货AA还各有不同平均窗口 |

**建议（LLM推断，未审核）**：库存以“相同SKU/店铺/仓库/时点/单位”的系统快照为核验依据，预测库存以经PO/货件核销后的滚动记录为计划依据，二者偏差另列校准原因。预计日销用历史基准加可解释活动增量，记录修改人、有效期和依据，而不是凭经验任选一个更好看的分母。

原文用词差异也要保留：两份公司SOP在“销量预估”处写【控制库存】字段，而工具公式实际将外部Col10用于控制销量、Col11用于预测库存；本报告不把这个原文表述默默改成一致。可能是旧版表头或笔误，需用对应版本源表确认，不能按字段名把库存件数当日销。

## 3. 「下单发货」实际公式：采购和发货分别算

本节引用「下单盘点-工具表-伟卿.xlsx」实际源公式（版本见台账）。引擎现有非空样例是MTJ产品，不是本报告主鞋架SKU；因此引用其通用公式设计，不宣称该行数据是鞋架算例。Google专属原式保存在公式证据.json，以下为去掉导出包装的中文拆解。

### 3.1 参数、日期与采购量

| 单元格 | 源公式/读取 | 解释与影响 |
|---|---|---|
| A2/B2 | TODAY()-WEEKDAY(TODAY(),2)+1；A2+21 | 本周一与其后21天，固定三周假设 |
| C2/D2 | A2-7；A2-1 | 上周周一至周日 |
| H4/I4 | VLOOKUP(A4,'SKU对应关系'!C:L,10,0)；VLOOKUP(A4,'SKU对应关系'!C:M,11,0) | MOQ取L，安全库存天数取M，**并非直接取「0」N列** |
| J4/K4 | E2+船代(同步)对应国家天数；-E2+SKU对应关系G | E2在船期和工厂交期之间一加一减，F2用于工厂日期；为空时按算术零解释也需检查假期参数 |
| N4 | A2+F2+K4+7-WEEKDAY(A2+F2+K4+7,2)+1 | 归到后续周一 |
| O4 | N4+J4-WEEKDAY(N4+J4,2)+7 | 归到周日，不是周一 |
| P4 | Col10取O至O+I（两端含），若最大值唯一则剔除，均值ROUND到整数 | 均值窗口I+1个自然日；唯一高峰是否真为刷单需业务解释，不能自动认定 |
| Q4/R4 | O当天Col11；日期>O的备注「预入N」之和 | 下单到货时预测库存加更晚预入 |
| S4 | ROUND((Q4+R4)/P4,0) | 当前到货时点可售天数 |
| T4/U4/V4 | O+7当天预测库存；日期>O+7预入；ROUND((T+U)/P,0) | 下个到货时点可售天数，仍使用P |
| W4 | V<I才取O起至O+14之前的控制销量合计；设ratio=合计/H，ratio<1用CEILING，否则ROUND，再乘H | 14天销量按MOQ倍数处理，**超过MOQ后是就近取整，可能少于14天需求** |
| X4 | IF(S>I,0,(I-S)*P+W)，报错显示「异常」 | 当前库存补到安全线，再加W。X本身没有再做MOQ/箱率取整 |

采购有两个不同门槛：W看V<I，X看S>I，否则进入补量。不能把它们统一写成“低于安全线就统一补14天”。例如需求740、MOQ500，W可能算500而不是1000；需求200则补500。这是原式边界演示，不是真实鞋架需求。

安全天数也有三个层次，不混成一个标准：公司「采购计划下单SOP」通常35天；公司「库存规划」常规稳定产品28—35天、新链接及低销量变体通常20—30天；当前引擎实际读取「SKU对应关系」M，US4122BL为30天。历史字典提到「0」N列15/20/23/30，不证明它就是当前引擎I列来源；最终参数应按实际公式与公司批准的SKU策略核实。

### 3.2 发货量

| 单元格 | 源公式/读取 | 解释 |
|---|---|---|
| Y4/Z4 | Q非空则Y=6；Z=B2+J+Y-WEEKDAY(B2+J+Y,2)+7 | 到货锚点归周日；不是实际出库日期 |
| AA4 | Col10日期≥Z-6且<Z+I-6，均值ROUND | 正好I个自然日，与P的I+1天且剔峰不同 |
| AB4/AD4/AC4 | Z当天Col11；AD；ROUND((AB-AD)/AA,0) | AD4保存为人工常数0，不能把历史字典中的AD自动提取逻辑当当前每行公式；当前行具体扣除口径缺线上核实 |
| AF4 | 控制销量日期≥Z-6且≤Z+8求和 | 含首尾共15个自然日，尽管标题写“14天” |
| AG4 | IF(AC>I,0,(I-AC)*AA+AF)，报错显示「异常」 | 补足安全库存再加AF；AC=I时仍返回AF |
| AE4/AH4/AI4 | 从日期≤Z或>Z的「预入/待生产」非截单备注读取 | AE取第一票；AH拼接符合条件备注；AI取未来第一条。预入和待生产的实物状态须另查 |

> **分析建议，未审核**：若未来在途到货晚于断货日，单纯把它加进总库存会掩盖时间缺口。采购/发货都应同时检查逐日库存最低点和批次ETA，不只看总可售天数。AD是人工值时，扣漏/重复扣都可能让AG失真。

### 3.3 鞋架真实样例与执行量边界

主键：US4122BL→「SKU对应关系」第59行；品名鞋架，MSKU USBJT4122BL，ASIN B0CNGTZ3B5，工厂武义铁铭工贸有限公司，交期G59=20天、MOQ L59=500、安全天数M59=30。店铺见「发货汇总」S3，不能把国家与店铺混为一维。

「下单汇总」第6行：I6=15000件，T6=16件/箱。X6=CEILING(15000,16)=15008件，U6=15008/16=938箱。这里的箱率取整不再保证500的整数倍；MOQ是最小订量还是订购倍数需采购确认，不能把MOQ等同箱率。

「发货汇总」第3行：E3=US4122BL，H3预发货=15000件，I3可发货=15000件；M3待生产备注和T3数量为#REF!，无法锁定对应PO与工厂可发数量。该行必须保留未核实标记，不能判定可直接发15000件。

例外鞋架：CA0XJ012-RB-4T→「审批表核对数据」第3/4行。上期待生产500、可发货500，本期均0，AH=0；AI保存500、AK保存-500，值得查一票500件去哪了。但没有货件/PO证据，不能擅自断言被截单；低销量时AI返回的是件数而非7天。

## 5. 两个附件的备货逻辑与鞋架工具有什么区别

### 5.1 先辨清文件关系与数据层

「跨境订货表汇总测算底表.xlsx」负责将ERP导出和销售数据整成订货基础：

- 「马来订货表」D6是商品编码，主数据来自「千易货品档案」；J6向右的历史销量来自「销量汇总透视表」。
- AO6可用量=SUMPRODUCT，匹配商品编码与仓库，读取真实子表「千易库存数据 」C列。**该子表名末尾确有空格**，不能删掉空格后假称原公式可用。
- AP6采购计划量取「采购计划单」匹配商品+仓库的H列；AQ6采购在途量取「采购订单清单」状态为新建/收货中/待审核/已下单的J列。
- AQ包含未审核/新建，不等于“已上船在途”；J列是否为未收余量、AP是否与已生成PO重复，本轮无法由模板名称独立确认。
- H2/I2以「到柜情况」筛国家、装柜地、距E1<30天求运输/清关均值，保存为#DIV/0!；原筛选未显式要求日期差≥0，未来日期是否混入需清理数据后复核。

「跨境订货在线表.xlsx」通过外链[1]引用底表多个区块；还含「库存查询」「运营销售目标」「计划清库存」等。它不是只展示底表：在线表自行算需求预估、安全库存、建议补货、断货与售罄日期，并允许人工覆盖。

### 5.2 在线表实际补货公式（马来订货表）

| 字段 | 公式设计与单位 |
|---|---|
| BJ 预估日销 | BJ6=BK6；BJ7为人工值6，没有公式；BN7写运营预估原因 |
| BK 历史加权日销 | BK6=BR6，BK7共享还原=BR7；BR取「库存查询」BK的30天日均。名为加权，样例实际是30天日均，未看到加权组合 |
| BS/BT/BU | 可用量/采购计划量/采购在途量，外链引用底表AO:AQ；不能一概当实物可用库存 |
| DR 标准差 | 排序后的30天日销量CN:DQ，去掉前两项后用CP:DQ，再只保留>0的值，STDEV，错误回0 |
| DS 服务水平 | J销量分类×K毛利分类查BS1:BV4概率矩阵，NORMSINV转Z后参与CI |
| CI 销售波动安全库存 | ROUNDUP(IFERROR(Z×DR×SQRT(CL+CM+CJ)/BJ,0),0)，单位是天 |
| CG 安全库存 | CH供应安全天数+CI销售波动安全天数；CH样例固定7天 |
| CF 目标覆盖构成 | CG+CL生产周期+CM运输天数+CK断货调整+CJ放假调整；CK为负的断货天数 |
| BY 是否补货 | BV<CF时显示补货；BV=(BS+BT+BU)/BJ，错误返回10000 |
| CC 建议量 | ROUNDUP(MAX(((CF+H3)×BJ-BS-BT-BU)/BX,0),0)，错误回0；单位实为箱 |
| BZ/CA | BZ由人填写，CA=BZ×BX；CA才是按填写箱数形成的补货件数，不等于CC自动执行 |

**真实附件样例 K0301058（磁吸带盖收纳盒，不是鞋架）**：BJ7=6件/天，历史BK7=5.44；BS/BT/BU均0，BX7=5件/箱，H3=9天，CH7=7，CI7=0，CL7=10，CM7=20，CK7=-30，因此CF7=7天。CC7=向上取整((7+9)×6/5)=20箱；BZ7空，CA7=0件。复算匹配保存值，但不证明6件日销、0安全波动或负30天调整合理。

**已发现的失效链**：J7=`VLOOKUP(G7,#REF!,5,0)`→DS7=#REF!→CI7经IFERROR变0。服务水平矩阵确实接入公式，却可能因分类断链而静默失效。另一例BX8=0，CC8保存0，由IFERROR掩盖箱率分母错误。看到0建议不代表真不用补。

## 6. 对照刘宝红：优势、劣势与最小改动建议

本节为基于原文和公式的综合判断，未经人工审核；不声称统计模型一定优于人工，也不量化未经回测的收益。

| 重点环节 | 可保留的优势 | 当前不足与理论依据 |
|---|---|---|
| 需求预测 | 鞋架用未来日期控制日销能表达活动；附件有历史默认和修改原因 | 缺冻结预测版本和误差复盘。刘宝红《需求预测和库存计划》行84—85、2518—2531强调基准预测加职业判断；趋势/季节产品应看预测误差，不直接把原始波动全当不可预测 |
| 安全库存 | SKU级天数易执行；附件把服务水平矩阵接到安全系数公式，能差异化 | 固定天数无明确目标概率；附件DR删最高两项并排除零日、CI吞错误，可能低估风险。低库存平台要求、周期库存与不确定性缓冲须分开；依据《三道防线》行1340—1408、1483—1500 |
| 交期与周期库存 | 两体系均显式纳入生产及运输，附件细分到柜 | 历史均值≠可靠承诺交期；只给平均交期无法覆盖供应波动。缩短交期能减周转库存，减少不确定性能减安全库存，不能全靠改安全天数；依据《需求预测和库存计划》行112—116 |
| 定期复查与补货 | 周度盘库、14天需求覆盖容易形成节奏；附件订货频率9天显式参与目标量 | 复查周期与供应提前期共同决定保护窗口，附件CI平方根中仅CL+CM+CJ，没有直接纳入H3；是否需扩展需按实际订单释放机制确认。此处为模型分析，不冒称书中原公式 |
| 分类与服务目标 | 附件销量×毛利分类可分配关注与缓冲 | ABC是价值/贡献分类，XYZ是波动/可预测性分类，两者不互相替代。当前J断链；不能把附件矩阵视为已实施XYZ。原文《三道防线》行354—355支持按离散系数差异化 |
| 执行闭环 | 鞋架审批权限、PO和两期核对能抓整票漏登；附件能显示多批在途时间风险 | 字符串解析与人工状态易丢批次；审批量不等于实物发货。应分清PO/批次/货件与在库/在途/待生产，减少事后校准 |

服务指标必须先定义：《三道防线》行1370—1383区分补货周期完全满足需求的概率和按数量满足的比例；《需求预测和库存计划》有时使用“有货率”泛指概率。这里DS的NORMSINV输入按“不缺货概率”解释，不能宣称DS=95%就保证95%需求件数满足，更不能承诺实际缺货天数。

建议按先后只做五件事（均为LLM建议）：

1. **先修证据与异常，不先换模型**：统一文件/子表/SKU/单位/截止日期，缺日销、缺箱率、分类断链必须显示原因。收益是避免假零；代价是维护字段契约与异常清单，需要ERP字段说明、原始导出和表主确认。
2. **做实一条鞋架PO闭环**：以SKU+完整PO子批次+货件为键，对上审批、采购计划、订单、出库、运输、接收；避免把已审待发当实物在途。需要PO与货件凭证，代价是首次清理历史重单；先解决可用量再谈安全天数。
3. **保留控制日销，新增冻结基准与活动增量**：至少区分版本、日期窗口、库存受限销量与正常需求，按稳定/促销/间歇类复盘。能解释预测修改，代价是留历史版本与活动记录，不能拿当前改过的预测回看过去自证准确。
4. **把安全库存拆开管理后小范围试算**：平台/渠道最低覆盖、需求预测误差缓冲、交期缓冲与周期库存分列；用相同时间单位和服务概率，在少量稳定SKU验证后再扩。需要误差历史、真实交期分布，代价是参数维护；不直接复制附件0波动项或固定7天。
5. **最后优化补货批量与脚本**：确认MOQ是最低量还是倍数，检查15天窗口及到货周锚点；在副本测试重复PO、拆单、失败恢复后才推进自动化。需要代码、权限和采购包装规则；优先最小改动，不替换整套流程。

## 7. 验证结果和仍需补证的地方

独立算术与离线护栏共26项通过，见校验结果.json：真实鞋架15000→15008件/938箱；真实附件96件缺口→建议20箱；W窗口14天、AF窗口15天；MOQ就近取整与安全线相等边界；原件与版本副本指纹一致。已制造缺源、零箱率、重复SKU+PO三类失败并观察明确报错，再恢复合法输入通过。

这些校验不是Google Sheets重算，不是Apps Script实测，更不证明未来不会断货。缺源、重复PO检测是本报告离线审计工具的护栏，原表自身部分IFERROR仍会吞错，不能据此称原表已经有同样保护。

尚缺：五张线上表完整名称与目标gid内容；鞋架未来日销/库存序列与建议量全链；真实脚本代码/函数/触发器/日志；库存系统原报告；主样例最终PO、出库与货件记录。获取前本报告为受限草稿，不能作为直接下单15008件或发15000件的执行指令。
