## 二、先认懂公式里的符号

> 以下符号解释和使用提醒为 LLM 讲解，未经人工审核；示例涉及的函数均见归档来源。

| 写法 | 白话意思 | 看表时怎么理解 |
|---|---|---|
| `A2` / `A2:A100` / `A:A` | 一个格 / 一段 / 整列 | 整列公式不一定只算当前一行 |
| `$A$2` | 固定这个格 | 下拉复制时仍用同一个参数 |
| `'产品信息表'!A:AF` | 另一张子表的 A 到 AF 列 | 单引号包住表名 |
| `""` / `<>""` | 空字符串 / 非空 | 空白显示不等于没有错误 |
| `&` | 把文字拼起来 | `"预入"&300` 得到“预入300” |
| `{A2:A10,B2:B10}` | 两列左右拼接 | 可建立临时查找表 |
| `{表1!A:D;表2!A:D}` | 两块上下堆叠 | 多事业部合为一张表；列数要相同 |
| `0` 或 `FALSE`，位于 VLOOKUP 末尾 | 精确匹配 | 查 SKU、PO 一般要求一字不差 |
| `TRUE`，位于 VLOOKUP 末尾 | 近似匹配 | 本库特殊用法是按行号找上一条非空记录 |
| `(条件1)*(条件2)` | 两个条件同时成立 | 数组运算里的“并且” |
| `(条件1)+(条件2)` | 至少一个成立 | 数组运算里的“或者”；结果可能为 2，不能当数量直接合计 |

## 三、跨表取数、筛选和合并

### 1. IMPORTRANGE：把另一份谷歌表搬进来

**实际作用**：同步船代时效、条码表、采购信息和物流货件，是各表的数据入口。[S1/S3/S4]

讲解示例：

```excel
=IMPORTRANGE("源表链接或ID","'产品信息表'!A:AF")
```

第一个参数是源文件，第二个是子表名和范围。它只负责搬数据，不自动判断这批货能不能发。新账号可能要授权；源文件删列、改名或撤权，下游会断。[S1]

### 2. QUERY：把取来的数据按业务条件挑出来

**实际作用**：筛选本周有“可下单量”的 SKU、按日期取采购明细、查询某个 PO 的物流。[S1/S3/S4]

讲解示例：

```excel
=QUERY(A2:F100,"select A,B,F where F > 0",0)
=QUERY(IMPORTRANGE("源表ID","'产品信息表'!A:AF"),
 "select Col1,Col23,Col7,Col31 where Col1 is not null",0)
```

第一条选出 F 列大于零的行，只返回 A、B、F。第二条从跨文件导入结果中挑第 1、23、7、31 列，且第 1 列非空。`Col23` 是**传入数据的第 23 列**，不一定是原表 W 列；导入起点变了，编号就变。

| 源表出现过的条件 | 作用 |
|---|---|
| `is not null` / `is null` | 留有数据 / 查缺数据 |
| `= 'PO…'` | 找完全一致的采购单 |
| `contains 'PO…'` | 找包含这段文字的采购单 |
| `ends with '待生产'` | 留下以“待生产”结尾的备注 |
| `matches '^FBA[0-9A-Z]+$'` | 留符合指定格式的货件号 |
| `order by Col1 desc` | 日期从新到旧，便于取最新记录 |
| `date '2026-11-01'` | 按日期筛选，日期文字格式要规范 |

**原表逻辑**：库存查询先按 PO 完全匹配，没结果时才改用 `contains`。[S4：查询(柳思）F2]

> 💡 LLM 复核提醒：包含匹配可能把 PO 主单和多个拆分单一起抓进来。查询有结果后，还要核对完整 PO、SKU 和数量，不能把“查到了”当成“一定匹配对了”。

### 3. FILTER：只保留满足条件的行

**实际作用**：去掉空链接，合并各品类的网址台账；过滤 MSKU 非字母开头的杂项行。[S1/S3]

```excel
=FILTER(I2:L100,REGEXMATCH(I2:I100,"^[A-Za-z]"))
```

讲解示例：保留 I 列以英文字母开头的记录，返回 I 到 L 四列。没匹配行时要区分“确实没有记录”和“数据入口断了”。

### 4. UNIQUE：列出不重复的编号

**源表原式**：`=UNIQUE(D:D)`。[S4：FBA库存数据(每周更新) A1]

作用：把同一货件的多行记录整理成一份编号清单，再用条件求和算各货件数量。它只去重，不负责把数量相加。

## 四、查找匹配：用一个编号补齐另一张表的信息

### 5. VLOOKUP：最常见的查表函数

**实际作用**：PO 查供应商、条码查 ASIN、SKU 查箱率、MSKU 查店铺、国家码查船期。[S1/S2/S3/S4]

源式加等号：[S2：星火发货统计汇总 R2]

```excel
=IFERROR(VLOOKUP(D2:D6864,'产品信息表'!A:AF,4,FALSE),"")
```

拆开看：D 列是要查的 PO；在产品信息表 A 列找；返回查找范围第 4 列，即供应商；没查到或发生其他错误时显示空白。

**一次返回多列**：[S2：同表 G2]

```excel
=IFERROR(VLOOKUP(D2:D6864,'产品信息表'!A:AF,{31,5,17,7,29},FALSE),"")
```

依次返回预计到货时间、采购员、品名、发货数量、待到货量，向右展开五列。右边的格子不能放别的内容。

**组合键匹配**：[S2：同表 Q2]

```excel
=IFNA(VLOOKUP(D2:D6864&S2:S6864,
 {'JOB ID汇总'!B:B&'JOB ID汇总'!E:E,'JOB ID汇总'!C:C},2,FALSE),"")
```

用“PO + ASIN”找 JOB ID，比只按 PO 更细。源表直接拼接没有分隔符。

> 💡 LLM 提醒：组合键应确保不会拼成同一串文字；新增设计可使用统一分隔符，但两侧要一起改。另一个风险是重复键：VLOOKUP 取首条，不会自动汇总多条结果。

### 6. XLOOKUP：查找列与返回列分开指定

**实际作用**：按“SKU + 工厂”查交期和 MOQ（最小起订量），并允许人工交期修正优先。[S1：SKU对应关系 G/L]

讲解示例：

```excel
=XLOOKUP(A2&"♦"&B2,'供应商表'!B:B&"♦"&'供应商表'!E:E,'供应商表'!J:J)
```

A2 为 SKU，B2 为供应商；同时匹配两个条件后返回非首批周期。一个 SKU 对多家工厂时，不能只看 SKU。

### 7—8. MATCH + INDEX：先找位置，再拿值

**源表组合**：[S2：产品信息表 H2，以下为单行讲解版]

```excel
=IFNA(INDEX('星火发货统计汇总'!C:C,
 MATCH(A2,'星火发货统计汇总'!D:D,0)),"")
```

MATCH 找到 PO 在 D 列的第几行，INDEX 返回那行 C 列的截单时间。MATCH 的 `0` 表示精确找。重复 PO 仍然只取首个位置，不能直接当作“最后一次发货日期”。

## 五、整列运算与多表批量处理

| 函数 | 白话作用 | 实际用途与来源 |
|---|---|---|
| ARRAYFORMULA | 一条公式同时处理一段数据 | 批量生成备注、批量提取国家码、自动带供应商等。[S2/S3/S4] |
| LET | 给中间结果起名字，后面重复用 | 把导入数据命名为 data，再筛日期、抽备注、算销量。[S1] |
| REDUCE | 按顺序处理清单里的每一项，逐次累计结果 | 逐个读取审批表链接。[S1] |
| VSTACK | 把几块数据上下叠起来 | 多张审批表合成快照。[S1] |
| LAMBDA | 定义“每一项要怎么算” | 配合 REDUCE、MAP、BYROW。[S1/S2/S3] |
| MAP | 对几列同一行的数据一起计算 | 截单日期 + 按国家及渠道匹配的船期。[S3：截单-星火 E2] |
| BYROW | 每次取一行做同一种计算 | 批量按 PO 回查截单日期。[S2：产品信息表 H2] |

**原表 MAP 组合**：[S3，原式加等号]

```excel
=MAP(F2:F2008,H2:H2008,I2:I2008,G2:G2008,
 LAMBDA(e,f,g,d,IF(e="","",
 IFERROR(INDEX('船代'!D:D,
 MATCH(LEFT(f,2)&g,'船代'!B:B&'船代'!C:C,0)),0)+d)))
```

F=PO、H=MSKU、I=发货方式、G=截单日期；逐行用“国家码+发货方式”找船期，再加日期。

> 💡 LLM 复核提醒：这条原式找不到船期会按 0 天处理，所以仍可能给出一个看似正常的日期。对计划员的影响是把截单当天当到货日；查不到船期应先补主数据。

**多表批处理骨架**：[S1，仅结构说明，不是可直接粘贴的完整原式]

```text
LET(链接清单,
  REDUCE(初始结果,每个链接,
    LAMBDA(累计结果,当前链接,
      VSTACK(累计结果,IMPORTRANGE(当前链接,统一范围)))))
```

先统一各源表字段和范围，再堆叠。字段同名但列顺序不同，直接拼会错位。

## 六、文本和正则：备注为什么也能参与计算

> “正则”就是按文字格式找内容，例如从“预入300，PO…”里取出 300。以下函数在 [S1/S2/S3/S4] 中均有使用。

### 16. REGEXEXTRACT：从文字里提取指定部分

讲解示例：

```excel
=VALUE(REGEXEXTRACT(M2,"预入(\d+)"))
```

从“预入300，PO261109005，待生产”提取 300；括号指定返回数字部分，VALUE 再把数字文字转成可计算的数值。[S1：预入量汇总逻辑]

| 源资料出现过的模式 | 提取对象 | 注意 |
|---|---|---|
| `\d+` | 第一个连续数字 | 备注以日期开头时会抓到日期，不一定是数量。[S1：发货汇总 T] |
| `预入(\d+)` | “预入”后紧跟的数量 | 写成“预入 300”可能匹配失败 |
| `(FBA[0-9A-Z]+|STAR-[0-9A-Z]+)` | FBA 或 STAR 货件编号 | 两种前缀都覆盖。[S4] |
| `^[A-Z]{2}([A-Z0-9]*\d+)` | 去掉开头国家码后提取一段编码 | 是源表分组规则，不代表所有 SKU 都适用。[S1] |

### 17. REGEXMATCH：判断有没有符合格式的文字

```excel
=REGEXMATCH(P2,"有透待注册")
```

透明计划判断会结合 ASIN 名单、注册状态和备注。备注含“有透待注册”也可输出“有透”。这只是源表标签逻辑，不能解释成已经注册成功。[S2：星火发货统计汇总 O2]

### 18. REGEXREPLACE：按格式删除或替换文字

源式简化：[S2：条码验证 N2；S1：LISTING F]

```excel
=REGEXREPLACE(H2,"-[A-Z]{2}$","-"&LEFT(C2,2))
```

把店铺名末尾的 `-US` 等国家后缀换成 MSKU 前两位；`$` 表示只改结尾。库存查询还用多层 REGEXREPLACE 去掉数量、日期和中文说明，留下 PO。[S4：查询 D2]

> 💡 LLM 提醒：这类清洗很依赖备注格式。改中文逗号、插入一段说明，都可能影响提取；清洗结果必须核对完整 PO。

### 19—24. LEFT / RIGHT / SPLIT / TRIM / TEXTJOIN / VALUE

| 函数与讲解示例 | 白话作用 | 实际用途 |
|---|---|---|
| `LEFT(F2,2)` | 取左边两个字符 | 从 MSKU 取国家码，查船期。[S3] |
| `RIGHT(F3,2)` | 取右边两个字符 | 从店铺字段取国家后缀。[S3：查询未发货PO C3] |
| `SPLIT(M2,"，")` | 按中文逗号拆开 | 备注拆成数量、PO、状态几段。[S1] |
| `TRIM(INDEX(SPLIT(M2,"，"),1,2))` | 取拆分后第二段并清理首尾空格 | 从规范备注取 PO；此为单行讲解改写。[S1：发货汇总 P] |
| `TEXTJOIN(分隔符,是否忽略空值,文本区域)` | 把多条文字连成一格 | 展示“本周能发货”的备注清单；参数为结构说明。[S1：下单发货 AH] |
| `VALUE("300")` | 文字数字转成数值 | 让提取的数量能参加求和。[S1] |

## 七、求和、计数和自动编号

### 25—27. SUM / SUMIF / SUMIFS

| 函数 | 用途 | 已用场景 |
|---|---|---|
| SUM | 直接合计一段数量 | 本周可下单总数、可发货总数、物流数量。[S1/S4] |
| SUMIF | 按一个条件合计 | 每个 FBA 货件对应入库数量。[S4] |
| SUMIFS | 按一个或多个条件合计 | 分开统计今天之前、今天当天的到货数量。[S4] |

源式：[S4：查询 C3/C4 内部计算]

```excel
=SUMIFS(K2:K6,N2:N6,"<"&$B$2)
=SUMIFS(K2:K6,N2:N6,$B$2)
```

K 为数量，N 为到货日期，B2 为今天。前者算今天之前，后者算今天当天。两段只覆盖第 2—6 行；更多明细是否被遗漏，要看线上范围是否扩展。

> 💡 LLM 复核提醒：源表的 `SUMIF(D:P,A1:A17965,P:P)` 条件区域横跨多列，不应当作标准单列范例照搬。更易读的讲解形式是 `SUMIF(D:D,A2,P:P)`，但这只是结构改写，仍需确认 D 列确为货件编号。

### 28—29. COUNTIF / COUNTIFS

**作用一：给重复 PO 自动加尾号。**[S2：产品信息表 B1]

COUNTIF 先判断一个 PO 出现几次；COUNTIFS 再计算“到当前行为止是第几次”。重复时生成 `PO…-1`、`PO…-2`，避免明细编号一样。

**作用二：避免同一商品同一天多条备注落在同一天。**[S3：下单-星火 C2；单行讲解版]

```excel
=IF(D2="","",G2+COUNTIFS($B$2:B2,B2,$G$2:G2,G2)-1)
```

同一 B 值、同一基准日 G 的第 1 条日期不变，第 2 条加 1 天，第 3 条加 2 天。**这是排布记录的规则，不是物流真实晚一天。**

### 30. ROW：拿到当前行号

用于判断第一行写表头、统计当前行之前的重复记录，以及“向下带出上一条非空采购单”的查找。[S2/S4]

采购信息向下填充的组合：

```text
ROW 生成行号 → FILTER 留下非空的行号和内容 →
VLOOKUP(当前行号-1,上面的非空清单,2,TRUE) → 带出上一条采购单
```

这里 `TRUE` 是有意的近似匹配，因为行号有顺序；不要把它直接搬去查无序 SKU。

## 八、下单、发货和库存的核心公式

> 本节除特别注明外来自 [S1]。公式骨架采用该归档字段说明，不代表已经重新核对当前在线原式。MOQ 是最小起订量，箱率是每箱件数；两者可能不同。

### 31—34. ROUND / CEILING / AVERAGE / ABS

| 函数 | 作用 | 业务例子 |
|---|---|---|
| ROUND | 按位数四舍五入 | 箱数保留 1 位、可售天数取整数、预计交期按周折算 |
| CEILING | 向上凑到指定倍数 | 可下单量 105、箱率 12，采购量凑到 108 |
| AVERAGE | 算平均数 | 算到货周附近的平均控制日销 |
| ABS | 去掉正负号，只看差距大小 | 库存差额÷预计日销，得到偏差天数的绝对值 |

**整箱采购**：[S1：下单汇总 X]

```excel
=IF(E3="","",CEILING(I3,T3))
```

I3 是可下单量，T3 是箱率；先向上凑整箱。`ROUND(105/12,1)` 只会得到约 8.8 箱，不能保证整箱采购。

**下单可售天数**：[S1：下单发货 S]

```excel
=ROUND((Q4+R4)/P4,0)
```

Q=到货周预测库存；R=该周之后预入量；P=该周平均控制销量。这个字段包含后续预入，不能读成“今天 FBA 实物还能卖几天”。P 为 0 时不能正常除。

**下周可售天数**：[S1：V]

```excel
=ROUND((T4+U4)/P4,0)
```

T/U 是下周库存、下周后预入量。W 列的正常补货量会结合 V 与安全库存天数 I 比较，再按 MOQ 取整。归档只给骨架，本文不臆造完整 W 原式。

**补足库存下单量**：[S1：X]

```excel
=IF(S4>I4,0,(I4-S4)*P4+W4)
```

够安全天数就不补；不足时，补足天数差对应的数量，再加正常周期补货量 W。等于安全天数时仍走后一分支，结果是否为 0 还取决于 W。

**发货口径可售天数**：[S1：AC]

```excel
=ROUND((AB4-AD4)/AA4,0)
```

AB=发货预计到货时点的预测库存；AD=需要扣除的未发货订单数量；AA=对应平均控制销量。**下单盘已下订单，发货盘能实际衔接的货，两种口径不要混用。**AD 的归档文字同时出现“在途”和“未发货”描述，属于待确认项，见十一。

**补足库存发货量**：[S1：AG]

```excel
=IF(AC4>I4,0,(I4-AC4)*AA4+AF4)
```

AC 足够就不发；不足则补缺口，再加正常发货量 AF。AF 按 Z 前 6 天至后 8 天抓取控制销量，实际包含多少日期取决于端点条件，不能只看字段名“14天”。

### 库存的两条线：实际库存与控制库存

[S5] 只有 CSV 值快照，下面是来源中通过数值反向验证的关系，**不是提取到的单元格原式**：

```text
今日实际在库 = 昨日实际在库 − 今日总销量 + 今日入库
今日控制库存 = 昨日控制库存 − 今日控制销量 + 今日入库
```

来源实例：179−6+190=363；179−4+190=365。两条线同一天都加了 190 件入库，但扣减的销量口径不同。

## 九、日期函数：什么时候下、什么时候到

| 函数 | 作用 | 本库使用位置 |
|---|---|---|
| TODAY | 返回今天日期 | 库存查询基准日、临近到货判断。[S4] |
| WEEKDAY | 日期对应星期序号 | 把日期归到统一周基准。[S1] |
| TEXT | 把日期/数字显示成指定文字 | `TEXT(K2,"MM.DD")` 拼交期；`yyyy-mm-dd` 拼 QUERY 日期条件。[S2/S3] |
| YEAR / MONTH / DAY | 提取年、月、日 | 年度、季度、截单日期备注。[S2/S3] |
| INT | 向下取整数 | 月份转季度：`INT((MONTH(C2)-1)/3)+1`。[S2] |
| DATE | 用年月日生成日期 | 核对表内 `DATE(2026,8,2)` 一次性校准条件。[S1] |
| DATEVALUE | 日期文字转日期数值 | 按发货距今天数找待跟进物流。[S4] |

### 本周一：注意那个 +1

[S1：下单发货 A2]

```excel
=TODAY()-WEEKDAY(TODAY(),2)+1
```

WEEKDAY 的第二参数为 2 时，周一为 1、周日为 7。2026-11-25 是周三，代入可得 11 月 23 日周一。

> 💡 LLM 复核发现：同一份 [S1] 的快照表 E1 写成 `TODAY()-WEEKDAY(TODAY(),2)`，却解释为“本周一”；按算式实际是 11 月 22 日周日。另一处带 `-7` 的写法也有同类偏移。来源内部不一致，必须回线上核对，本文不替它静默改正。

### 到货日期 = 基准日期 + 交期/船期，但“归周”还会改日期

[S1：下单发货 N/O/Z] 有归周公式；不能只看字段名认定是周一。

```excel
N4=$A$2+$F$2+K4+7-WEEKDAY($A$2+$F$2+K4+7,2)+1
O4=N4+J4-WEEKDAY(N4+J4,2)+7
Z4=$B$2+J4+Y4-WEEKDAY($B$2+J4+Y4,2)+7
```

> 💡 LLM 复核：N 式把基准日归到下一周的周一；O/Z 的末尾为 `+7`，按星期序号算归到周日，归档却称周一。这里先保留公式与矛盾，不能用说明文字覆盖算式。

[S1：下单汇总 Y] 交期骨架：

```excel
=E1+1+ROUND((4+VLOOKUP(E3,'SKU对应关系'!C:I,5,0))/7,0)*7
```

> 💡 LLM 复核：来源写“按周向上取整”，但 ROUND 是四舍五入。例如交期 12 天，加缓冲 4 天为 16，除以 7 后四舍五入得到 2 周，即 14 天，并非向上得到 21 天。是否符合当前业务规则需确认。

## 十、判断、校验和异常处理

### IF / IFS / AND

- **IF**：条件成立用结果 A，否则用 B。源表常用“PO 为空则空白”“有拆单后数量则优先用拆单数量”。[S2]
- **IFS**：依次判断多个条件。快照表按控制日销和实际日销分档，给 15/20/23/30 等安全库存天数。[S1] 这是旧表策略，不能当所有产品统一标准。
- **AND**：条件全部成立才为真。核对表用它识别前后都没有相同 SKU 的新记录。[S1]

条码/品名核验的单行讲解版：[S2：星火发货统计汇总 T/W]

```excel
=IFERROR(IF(I2="","",IF(U2=I2,"OK","填写有误")),"")
```

有填品名时才核对，匹配则 OK，否则提示错误。原式中一旦查找报错也会空白，因此“没报错文字”不能等同通过。

### IFNA / IFERROR / ISNUMBER / ISBLANK

| 函数 | 作用 | 业务上要注意 |
|---|---|---|
| IFNA | 只接住 `#N/A` | 多用于没找到匹配记录时给空白/提示 |
| IFERROR | 接住多种错误 | 除零、断链、匹配失败都可能被吞成空白或固定文字 |
| ISNUMBER | 判断结果是不是数字 | `ISNUMBER(MATCH(...))` 用于判断是否在名单中。[S2] |
| ISBLANK | 判断格子是否为空 | 海外仓物流判断预计/实际到货是否缺失。[S4] |

> 💡 LLM 提醒：ISBLANK 对“真空格”和“公式返回空字符串”的结果可能不同。断链时不要先套更多 IFERROR，应先检查源表、授权和范围。

### 三类滚动对账：别把差额当库存

下列是 [S1：审批表核对数据] 的业务骨架：

| 检查 | 算什么 | 异常意味什么 |
|---|---|---|
| 待生产衔接 | 本周待生产 −（上周待生产 + 上周可下单 − 上周可发货） | 可能漏记下单或状态变更 |
| 库存/在途消耗 | 上周 FBA+AWD+在途 + 上周可发货 − 本周 FBA+AWD+在途 | 其中含正常销量消耗，不能非零就判错 |
| 在途衔接 | 本周在途 −〔上周在途 + 上周可发货 −（本周 FBA 增量 + 实际日销×7）〕 | 可能在途没接上、漏登记或截单变化 |

核对区的“待生产”“在途”是**对账差额**，原始填报区的同名列才是数量。差额为 0 通常是衔接上，不是没有货。相邻两行是否同 SKU、上下周顺序是否正确，会直接影响计算。[S1]

### 库存查询的数量差

[S4：查询 C2] 使用“物流数量合计 − 备注中提取的数量”。例如备注记 36、物流合计 200，差额为 164。差额只说明两处口径不一致，不能单凭它认定多到货或漏到货。

### 临近到货跟进标记

[S4：物流数据-欧/亚/大洋 O2] 会检查：未填写到货日期，且预计到货在今天后 14 天以内；或者预计到货也没填，且发货已超过固定天数，就标“是”。欧表使用 30 天阈值，亚/大洋使用 20 天。这个“是”是待跟进标签，不是已到货凭证。

## 十一、使用前必须知道的限制与待确认项

| 问题 | 已有证据 | 对计划决策的影响 |
|---|---|---|
| 导出兼容占位 | [S1—S4] 出现 `__xludf.DUMMYFUNCTION` | 这是导出表示，不能当成谷歌函数名复制；外层 IFERROR 的固定值也不能解释为业务默认值 |
| 日期文字与算式不一致 | [S1] 多处周一/周日、ROUND/向上取整冲突 | 可能抓错一天或错一周，必须看线上单元格 |
| 待生产与在途文字混用 | [S1] AD 描述同时出现“未发货”“已发货在途” | 确认过滤条件到底扣哪些批次，避免重复扣减 |
| 短历供/长历供/模拟历供没有原式 | [S5] 仅 CSV 值快照 | 30/90 天、库存分子范围及取整方式只是来源推断，不列为已核实原公式 |
| “预入”不是完整状态 | [S1/S3/S4] 待生产、截单备注均可含预入 | 必须结合待生产/截单/AWD 等后缀判断，不能把全部预入都当作已发货 |
| 源表部分固定范围较短 | [S4] K2:K6 等 | 新增明细后可能漏算 |
| 单行与数组公式不等价 | [S2/S3/S4] 有整列及多列展开 | 讲解示例粘回原表前须恢复数组范围，并给展开区留空 |
| 表头有错位 | [S1] K 写工厂实为交期，L 实为工厂，N 实为日期 | 不按表头盲改，先看公式与上游字段 |

## 十二、推荐怎么学、怎么查

> 💡 以下为 LLM 使用建议，未经人工审核。

1. **先学 IF、VLOOKUP、IFNA**：先能回答“这个数从哪来、没匹配到会怎样”。
2. **再学 QUERY、IMPORTRANGE**：看懂整套表的数据入口和筛选条件。
3. **接着学 REGEXEXTRACT、REGEXMATCH、文本拼接**：看懂为什么备注写法会影响数量。
4. **最后看 ARRAYFORMULA、MAP、LET 等**：理解整列和多表批处理，避免覆盖展开区。
5. 改计划公式前依次核对：SKU/工厂/国家和渠道 → 基准日 → 日销口径 → 库存是否含待生产与在途 → MOQ/箱率 → 输出数量与到货日。
6. 看到空白先查“真没数据还是报错被藏了”；看到大额建议先核对上周下单/截单是否已经回填。
