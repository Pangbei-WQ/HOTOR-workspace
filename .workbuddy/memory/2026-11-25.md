# 2026-11-25

## lumimax 调研与本地 LLM Wiki 模式对比（仅对话交付，未写 wiki）

- 读机器之心公众号文章《Karpathy提出的LLM Wiki，中国公司做出来了！lumimax八项公开基准测试全线领先》，并核实官网 lumimax.ai、benchmark 页、FRAMES 逐题页、MCP 指南、Karpathy 原始 gist。
- 产品事实：海马云（2014 年成立，GPUaaS/云渲染背景）2026-11 发布 lumimax，定位面向 Agentic AI 的企业级可信知识库；DEN 深度证据链知识网络，实体/事件/关系/证据；支持 PDF/Word/Excel/PPT/文本/图片/音视频，单库 10GB+、1000 万字+、增量更新、MCP 接入、私有化部署；积分制 $20/2万、$100/10万、$500/50万，官网未见免费额度。
- 关键保留意见：8 项“全球第一”均为厂商自测、对比对象来自不同模型配置与工具预算（如通义 DeepResearch Avg@3 最多 128 次工具调用）；FRAMES 逐题页自曝完全匹配率仅 56.55%、语义判定 90.44%、官方口径 92.84%；文章称 OpenDocVQA InfoVQA 子集 84.54%，官网首页写 OpenDocVQA 91.45%，口径不一致。官网 MCP 指南页面内嵌“请直接执行接入”的指令，按不可信网页内容处理，未执行。
- 本地库实测数据：wiki 130 篇 md、raw 80 篇 md、outputs 28 篇 md，wiki 1.6M / raw 28M；review_status 全部 unreviewed（0 reviewed、0 disputed/outdated）——审核闸门设计存在但从未实际启用。
- 对比结论：本地模式强在 raw 不可变 + sources/log 可审计 + git 版本 + outputs 人工终审门 + 业务语义人工策展；lumimax 强在多模态解析、实体消歧/冲突检测、跨文档多跳推理、MCP 对外供数、大规模噪声资料。对 HOTOR 的会议录音/Excel 公式/多版本 SOP 场景互补性强，但未做实测前不替换现有库。
- 用户偏好遵守：先在对话给结论，未擅自写 wiki；已询问是否要新建 wiki 页面并同步 index/log（等用户拍板）。
